# T3.9 执行记录（把 PostGIS 接进工具层 —— M3 后的第一补项）

> 只写实测。数据库：本机 PostgreSQL 17.5 + PostGIS 3.5.2。

## 一、为什么有这一轮

M3 的退出记录把「**PostGIS 尚未接入工具层**」列为第一补项 ✓：目录/分页/瓦片/过滤器都在**服务层**可用并被真库验证，但模型**看不到** PostGIS 数据 ✗。本轮把它接上 ✓。

## 二、交付物

| 文件 | 职责 |
|---|---|
| `packages/gis-postgis/src/opener.ts`（新） | `postgis:<profile>[/<schema>.<table>]` 地址 → 数据集（**纯工厂**，不连接 ✓，layers 是占位 ✓） |
| `packages/gis-postgis/src/handler.ts`（新） | `kinds: ['postgis']` 的 handler：inspect（目录 + 估算范围 + **估算标注** + `tiles: true`）、query（绑定的 where、分页、geojson/wkt） |
| `packages/gis-postgis/src/index.ts`（改） | 用**可选** `ctx.inject(['gis'])` 注册 opener 与 handler ✓（缺 gis-core 时本行仍能加载 ✓，契约 #19） |
| `packages/dsh-gis/cordis.patch.yml`（改） | **挂上 `gis-postgis` 行** ✓ |
| `scripts/t3-postgis-tools-check.mjs`（新，`check:postgis-tools`） | 真实例：从地址开到分页到过滤器，全程真库 |

## 三、真实例实测（14 项全过）

在一个真实例里（探针调用与工具**同一个** `ctx.gis` 门面 ✓，不碰内部 ✓）：

- `gis` 与 `gisPostgis` **都已发布** ✓
- `gis.open('postgis:live/dsh_gis_fixture.cities')` → opener **认领地址** ✓、数据集**有派生 id** ✓、**带 profile 名而没有任何口令** ✓
- `inspect` → 列出可达的空间表 ✓（含 fixture 五张 ✓）、**SRID 4326** ✓、**估算范围** ✓、`tiles: true` ✓、**明确标注「行数与范围是估算」** ✓
- `query` → **真的从数据库取回一页** ✓、几何是 **GeoJSON Point** ✓、属性可用 ✓
- `where: 'population > 39000'` → **过滤器经工具路径到达数据库** ✓（返回 1 行 ✓）
- `geometry: 'wkt'` → **WKT 编码被遵守** ✓
- 无任何步骤失败 ✓

## 四、🔴 一个真陷阱（已记入契约 #50）

探针最初用 `gis.resolve('postgis:…')` ✗ 得到「未注册」：**`resolve` 只接受 id，路径必须走 `open`** ✓（`open` 才会去问 opener 并登记结果 ✓）。工具层早就做了这个区分 ✓，但服务 API 的两个名字看起来都能用 ✗ —— 记下来，省下一次同样的排查 ✓。

## 五、两处需要你知道的**环境改动**

1. **用户的 profile 被加了一条 link 依赖** ✓：`~/.dsh/profiles/gisweb/package.json` 增加 `"@znlgis/dsh-gis-postgis": "link:D:/self/code/dsh-gis/packages/gis-postgis"` ✓，并在其 `node_modules/@znlgis/` 下建了同名**目录联结** ✓（附加、可逆、无网络 ✓）。没有这一步，任何实例都会对新增的 `gis-postgis` 行报 `failed to import` ✗。
2. **bundle patch 现在挂这一行** ✓ ⇒ **重启 GUI 后**插件会加载它 ✓。

## 六、诚实边界

1. **一个 profile 能看到它账号可达的**全部**空间表** ✓（实测本机列出 **42 张**，含用户自己的数据与 PostGIS tiger 扩展 ✓）✗ —— 目前没有「按 schema 白名单限定」的配置面 ✓。这是**行为**而非缺陷 ✓，但生产使用前应当补一个 schema 过滤选项 ✓。
2. **瓦片尚未暴露为路由** ✗：`capabilities.tiles: true` 且 `mini` 的 `tile()` 已可用 ✓，但没有 `/api/gis/tiles/...` ✓（前端还画不到库直出的瓦片 ✗）。
3. **`bbox` 过滤未接** ✗：handler 的 query 尚未把 `request.bbox` 变成 `ST_Intersects` 条件 ✓（分页/过滤器可用 ✓，空间窗口还不行 ✗）。
4. **未接 UI**：设置卡片不显示 PostGIS 剖面状态 ✓。
5. **未压测**：42 张表的目录查询与分页都很快 ✓，但未做并发或大表测试 ✓。
