## 三、五个设计决定

1. **控制器与 React 外壳分离。** 地图出问题的形态全是生命周期：库比容器晚到、卸载比加载快、observer 活得比画布长、状态回调打进已卸载的组件。把这些放进**无框架**的 `createMapView`，就能在 Node 里用假 MapLibre 断言（本项目方法论：结构化解耦优先于 mock 整个环境），React 那层只剩状态渲染。
2. **两级懒 chunk，一层一个关注点**：入口 → `client.GisMap.js`（组件 + 控制器 + 自己的样式 + MapLibre 的 CSS）→ `client.maplibre.js`（库本体 1.47 MB）。库先到也没用，组件先到也没用；两者都不在首屏。
3. **销毁是幂等且能赢过加载**：`destroy()` 会 `await` 那次加载，晚到的模块看到 `destroyed` 就**什么都不创建**；`map.remove()` 只调一次；observer 只断一次；销毁后的状态回调一律丢弃。
4. **样式跟着 chunk 走**：`map.module.css` 与 `maplibre-gl/css` 都只被 `GisMap.tsx` 引用，**eager 图里没有任何一条边通向它们**（契约 #10：共享 CSS Module 会被提升成入口同步 require 的 chunk）。
5. **不画不出来的东西要出声**：T2.1 只画 `geojson`；`raster`/`mvt` 走 `LAYER_KIND_UNSUPPORTED` 上报（这两个源属于 T2.2/T2.4）。**默认样式按 `style.type` 走，缺省 `circle`**——几何感知的默认值留给 T2.2，因为那需要先看数据。

## 五、实现前先读源码，省下两次返工

**1. MapLibre 必须锁 5.x，不能 6.x。** 写第一行代码前先读了库的 worker 装载方式：6.x 是纯 ESM，用 `new URL('./maplibre-gl-worker.mjs', import.meta.url)` 取 worker；而我们的 chunk 由 `/plugins/<pkg>/...` 提供，那个兄弟文件根本不存在——**地图会静默起不来**。5.x 的 UMD 把整个 worker 内联成字符串，装载时 `setWorkerUrl(URL.createObjectURL(new Blob([...])))`，自包含。已写死 `^5.24.0` 并把这条前提固化成 `check:bundle` 的断言。

**2. 对 CJS 包做动态 import 不会变成懒 chunk。** 第一次构建直接失败：

```
[plugin dsh-client-async-chunk-require]
Error: client bundle compiler: dynamic chunk "./client.maplibre-gl.js" has no generated import expression
```

rolldown 对 UMD 包生成的是 `Promise.resolve().then(() => __toESM(require('./client.maplibre-gl.js')))`，预设只认 `require(...)` 那一种形状。**幸而是构建期硬失败**（这是 M0 复刻 preset 时就设计好的门禁）。解法：加一层 ESM 包装模块 `map/maplibre.ts`，让互操作发生在 chunk 内部，调用点保持干净的 ESM 动态 import。

两条都已进运行时契约（#22、#23）。

## 六、诚实边界

1. **地图还没有产品面。** T2.1 的组件只挂在 M0 探针卡片的**开发按钮**上（点一下挂载、再点卸载）。真正的面是 **T2.6** 的 `gis_render` 卡片，而它要等 **T2.3** 的 `/api/gis/blob?id=` 才有数据可取——所以**「地图真的画出了要素」这件事本次没有验证**，验证的是产物契约、生命周期与首屏。
2. **只画 GeoJSON。** `raster`（COG/WMS 瓦片，需要 T2.4 的协议）与 `mvt`（T2.5/T3.4）都会上报 `LAYER_KIND_UNSUPPORTED`。默认样式 `circle`；几何感知的默认样式与 `--dsw-alias-*` 的完整样式模型属于 **T2.2**。
3. **WebGL 渲染本身没有断言。** 真实浏览器检查跑到了「首屏不取 MapLibre」为止；`new maplibregl.Map()` 在真实页面里的初始化（含 blob worker 是否被 CSP 放行）要等 T2.6 有面时才可验。
4. **`check:browser` 需要本机有 Playwright Chromium**（本机已有 `ms-playwright/chromium-1223`）与 `playwright-core`（已作为根 devDependency 加入）。它不在 `pnpm test` 里——它是实例级验证，T2.10 会把 Web e2e 正式纳入 `pnpm test:web`。
5. **`pnpm check:bundle` 读的是构建产物**，所以不在 `pnpm test` 里（干净检出没有 `lib/`）。已加进 `package.json` 的 scripts，T5.3 的 CI 应当串在 `build` 之后。
