## 三、M0 的七项发现（按重要性）

### 1 ⚠️ 发布的 npm 包不可按 `latest` 使用，必须锁 `alpha` 通道

```
@deepseek-ai/dsh-tools dist-tags: { latest: 0.0.1-rc.1, next: 0.1.5-rc.3, alpha: 0.1.7-alpha.2 }
```

- `latest`（`0.0.1-rc.1`）是**陈旧的稀疏发布**，且经镜像安装会因依赖一个**从未发布**的 `@deepseek-ai/dsh-type-meta` 而失败（npmjs 与 npmmirror **都 404**）；
- **可用通道是 `alpha` = `0.1.7-alpha.2`**，与本 checkout 的 `0.1.7-alpha.1` 同代。

**影响**：这是设计里风险 2（内核 alpha、扩展点会变）的**具体化**，且比原判断更严重——不是「升级可能破坏」，而是**默认安装路径直接装不上**。插件必须显式锁 `alpha` 通道版本；设计第十六章与附录 B 都要写死这条。

### 2 ⚠️ pnpm ≥10 的构建脚本门禁必须显式放行

`pnpm install` 首轮失败：`ERR_PNPM_IGNORED_BUILDS: esbuild@0.28.2`。pnpm 生成的占位符揭示了正确写法（与设计第十六章 git 安装那段一致）：

```yaml
allowBuilds:
  esbuild: true
```

**影响**：设计第十六章讲的「用户需要 allowBuilds 放行」**在纯 npm 依赖场景下同样存在**，不只是 git 安装。README 必须写。

### 3 ⚠️ 客户端 bundle 的值导入闭包只有 4 个文件

8 个候选文件里，`modules/src/client/entries.ts`、`system.ts`、`entry-lifecycle.ts` **都是类型导入、编译期擦除**。这让「复刻 preset」从「搬 1685 行」缩小到「搬 4 个文件 + 重写 4 处 specifier」，T0.4 的实际成本**低于计划估算的 1.5 人日**。

### 4 🔴 **eager 与 lazy 共享模块会产出「同步 require 的 chunk」——被加载器协议禁止**

首轮构建时，`card.module.css` 同时被 eager 组件与 lazy 组件导入，rolldown 将其提升为共享 chunk，入口于是出现：

```js
const require_card_module_css = require("./client.card.module.css.js");   // 同步！
```

而 `client-modules` 的协议明确写着「entry and chunk outputs **cannot synchronously require** another relative `client*.js` output」——**这会在运行时炸**。

修法：让 eager 与 lazy 各自持有自己的样式模块（`card.module.css` / `detail.module.css`），使两个图不共享任何模块。重建后同步 require 消失。

**影响**：这是一条必须写进设计的**实现级规则**——「eager 与 lazy 图之间不得共享模块」。第 40 项（工具清单漂移）之后，这是第二条「靠构建才发现」的约束。

### 5 宿主半 tsdown 的两个坑

- **`clean` 默认 true 会先删掉 `lib/`，而入口正位于 `lib/types/`**（tsc 刚产出）→ 报 `UNRESOLVED_ENTRY`。必须 `clean: false`。DSH preset 对客户端半有同样注释，宿主半需要自己设；
- tsdown 的 ESM 默认扩展名是 **`.mjs`**，而 `package.json` 的 `main` 是 `lib/index.js` → 需 `outExtensions: () => ({ js: '.js' })`。

### 6 `ctx.subprocess.spawn` 省略 `cwd` 会抛出难以理解的 TypeError

```
runner-launch.ts:292  if (value.includes('\0'))
TypeError: Cannot read properties of undefined (reading 'includes')
```

`targetEnvironment` 在**墓碑过滤之前**就无条件校验 `spec.cwd`，所以漏传 `cwd` 得到的是一句无关的报错。**插件的执行封装必须始终显式传 `cwd`。**

### 7 `--patch` 叠加与 Layer 组合行为符合预期

`--dump-config` 正确显示本层，且插件路径被规范化为 `file:///` URL。

## 九、本轮新增的两项发现（第八轮实测）

### 8 `clientBundle` 必须同时产出 node 半，否则加载即失败

首轮实测直接报 **`dsh-ui-gis (@znlgis/dsh-ui-gis): failed to import`**。原因：我的精简 preset 只产出浏览器半，而**客户端包的 Loader 行按裸包名解析到 `lib/index.js`**——宿主半没构建，行就导入失败。DSH 的 `clientBundle()` 之所以同时产出两半，正是这个原因。

已改：`clientBundle(id, options)` 现在返回 **`[nodeHalf, browserHalf]`**（`libEntry: null` 可关掉 node 半）。这条要写进设计 3.7 的硬约束清单。

### 9 客户端代码的类型检查需要「声明插槽的那个包」

`ctx.slots` / `ctx.locale` 不存在于裸 `Context`：它们由客户端包**声明合并**而来，且**必须 import 声明该插槽的包**才能把 key 放进 `SlotMap`。实测踩到的连锁错误：

- `Property 'slots' does not exist on type 'Context'` → 需 `import type {} from '@deepseek-ai/dsh-client-ui-renderer/client'`；
- `'tool.call.toolview' is not assignable to type '"root"'` → 需 `import type {} from '@deepseek-ai/dsh-client-ui-tool/client'`；
- `'uiGis' is not assignable to 'keyof LocaleNamespaceMap'` → 需自己 `declare module '@deepseek-ai/dsh-client-ui-slots' { interface LocaleNamespaceMap { uiGis: ... } }`。

另有一个**易错点**：`@deepseek-ai/dsh-client-ui-slots` **只有 `.` 导出、没有 `/client` 子路径**——照抄仓内 `import type {} from '...ui-slots/client'` 会报模块找不到。

### 10 `plugins.bundle.config` 的卡片拿不到 `form`——必须自取，且用**行 id** 而非包名

这是本轮最有价值的一条，因为它**表面上完全看不出来**：`PluginConfigViewProps.form` 是可选属性，示例与文档都暗示它会被传入。但读渲染该插槽的那一行源码才知道：

```tsx
// PluginManagerPage.tsx:584 —— bundle 配置：只传 view
{renderSlot('plugins.bundle.config', { view: 'page' }, { entryKey: pkg.name })}

// PluginManagerPage.tsx:500 —— 行配置：页面给表单
{renderSlot('plugins.row.config', { view: 'page', form }, { entryKey: key })}
```

所以 **bundle 级配置卡片必须自己取表单**，且命名空间是 **Host 条目 id（Loader 行 id `dsh-gis`）而不是包名**（`config-form.ts:289-302`）。第一版卡片按包名取、并等页面注入 `form`，于是 `form` 永远是 undefined、保存按钮永远禁用——**而卡片本身渲染正常**，看上去像「DSH 没给数据」。

改法：客户端 `inject: ['configForms']`，经一个模块级访问器交给组件，用 `ctx.configForms.get('dsh-gis')` 取表并 `subscribe` 订阅快照。

### 11 `.volatile()` 的 Config 不能加 `Schema<Config>` 标注

`const Config: Schema<Config> = Schema.object({ probeLabel: Schema.string().volatile() })` 在 `exactOptionalPropertyTypes: true` 下类型冲突（`Volatile<string>` vs `string`）。按 settings-card cookbook 的写法**去掉标注**即可。
