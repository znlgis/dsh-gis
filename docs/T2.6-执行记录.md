## 三、四个设计决定

1. **一个值，两个投影。** `execute` 返回 `RenderValue`；`render` 把它变成模型读的散文（与卡片出现之前的文本一致），`presentationMeta` 把它投影成**有界、无字节**的地图描述。落进会话日志的是后者，于是**回放不需要重跑任何东西，也不需要在转录里塞进一个坐标**。
2. **卡片是持久化块上的纯函数。** 判定放在 `mapCardState(block)`：它只读会话日志会持久化的字段（`kind`/`call`/`isError`/`error`/`meta`/`content`），React 那层只负责画。**这就是判据本身**——同一个日志永远得到同一张卡。块类型是**结构化**的（只声明四个它真正读的字段），因此不需要为它把聊天包拖进地图的懒 chunk。
3. **卡片在懒 chunk 里，槽位上是急切 shim。** 槽位注册需要一个组件，而卡片绝不能进首屏：注册的是 shim（先显示占位），它在挂载时把真正的卡片拉进来。于是一段塞满历史渲染的转录，在有人真的把某张卡滚到屏幕上之前**一个字节都不下载**。
4. **今天画不出来的要出声。** 只有 GeoJSON 有浏览器可直读的字节路由（T2.3）；shapefile / GDB / NDJSON / 连接类各自带一条 `UNSUPPORTED_FORMAT` 说明去卡片上（「空白地图不配解释」）。服务端 PNG 照旧产出，路径照旧进散文给模型。

## 四、实测

- **客户端纯度 8 条**：同一条块与其 **JSON 往返 + 深度冻结**的「回放副本」得到**完全相同**的状态；对七种块形态（运行中带/不带可解析参数、成功、失败、`call === null`、无 meta、meta 畸形）逐一比较；冻结的块不抛异常（证明确实只读不写）。
- **宿主投影 6 条**：GeoJSON 得到自己的字节路由 + 默认样式；四种画不出的 kind 各得一条**说明原因**的 note；描述**无字节**且**有界**（20 层 → 8 层）；散文含绘制数、尺寸、范围、CRS 与全部 issue。
- **产物契约 23 条**：新的 chunk 图（入口 → 卡片 chunk → MapLibre chunk）里每一条都被断言，包括「入口不静态 require chunk」与「无孤儿 chunk」。
- **真实浏览器 7 条**：客户端半加载、工厂执行、**首屏不取卡片 chunk / 地图 chunk / MapLibre chunk**、无页面错误、MapLibre 在真实页面可初始化并出画布。

## 五、🔴 本轮抓到的缺陷（又是产物检查抓的）

**卡片 chunk 同步 require 了组件 chunk。** `check:bundle` 直接报出来：

```
FAIL  client.GisRenderCard.js has no synchronous require of a chunk -- ./client.GisMap.js
```

根因：共享地图组件有**两个导入者**——探针卡片的开发按钮（急切图里的动态 import）与卡片（静态 import）。rolldown 于是把它提升成独立 chunk，卡片 chunk 便**同步** require 它。这与 T2.2 那次（eager 运行时 import lazy 模块）**是同一类错误，只是深了一层**：那次是「跨图共享」，这次是「两个动态导入者 + 一个静态导入者」。

修法：**撤掉 T2.1 的开发按钮**。它的注释当时就写着「直到 `gis_render` 卡片落地为止的开发面」——T2.6 正是那个时刻。撤掉后组件被内联进卡片 chunk，链路变成干净的「入口 → 卡片 → MapLibre」。

**这条值得记住**：共享 chunk 的触发器不止一种。判据只有一条——**产物里每个 chunk 都必须能从入口经 `require.async` 到达，且没有任何 chunk 被同步 require**。

另一处小坑（4 轮构建才过）：`output.presentationMeta` 必须返回契约的 `JsonValue`，而 **TypeScript 的 `interface` 没有隐式索引签名**，所以「看起来完全 JSON」的接口并不满足 `JsonValue`；编译器的原话是 `Index signature for type 'string' is missing`。改成 `type` 别名即可（并已写进源码注释，免得下次再踩）。

## 六、诚实边界

1. **卡片在浏览器里的真实渲染没有端到端验证。** 要看到它，需要一个**含 `gis_render` 工具结果**的会话：本机没有模型凭据，也没有现成的会话日志可回放。本轮的验证是「判定函数对同一日志给出同一答案」+「产物图正确」+「客户端半在真页面里干净加载」。**把这张卡真的画出来属于 T2.10（Web e2e，计划里 1.5 人日）**：造一个合成会话（或一次真实调用）后，卡片渲染、回放一致、三种降级都要在那里断言。
2. **`isError` 与 `call === null` 两种降级已实现并有单测**（T2.6 不实现它们卡片根本画不出来），但**「id 404 → 数据已不可用」是 T2.7 的判据**，本轮未做；三种降级的 e2e 断言同样在 T2.7/T2.10。
3. **卡片不显示服务端渲染的那张 PNG。** 这是设计 6.3 的取向（卡片是地图，PNG 是给模型的快速一瞥），模型读到的散文里仍有 PNG 路径。
4. **矢量/栅格图层的卡片链路仍未验**：`/api/gis/tile`（T2.5/T3.4）与 COG（T2.4）不存在，所以卡片今天只会画 GeoJSON（其余各自带说明）。
5. **探针卡片的开发按钮已撤**（见第五节）。M0 的详情按钮保留，它仍是产物契约的活证据。
