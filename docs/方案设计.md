# dsh-gis 方案设计

> 目标：让 DeepSeek Harness（以下简称 DSH）**更懂 GIS**、能**展示 GIS 数据**、能**浏览 GIS 数据**、能**调用现有 GIS 工具**。
>
> 本文是设计方案，不含实现。所有 DSH 扩展点均已在 checkout 中核对到具体文件/行，标注为「已核实」。

**怎么读这份文档**：一~二章看结论与现状；第三章是 DSH 扩展点地图（**实现前必读**，尤其 3.4 数据契约与 3.7 硬约束）；四~五章是架构与仓库结构；六~九章是四条能力主线（知识注入 / 工具 / 展示与浏览 / 格式 / 零服务预览 / OGC 服务）；十~十一章是 GDAL-QGIS 接入与设置页；十二章是安全底线；十三~十六章是路线图、风险、测试、发布。

**要动手时只需看三处**：附录 A（工具总表）、附录 B（配置项总表）、第十三章第 0 步。其余是设计与论证。

## 一、结论先行

**产品定位**：dsh-gis 不是一个独立应用，而是一个 **DSH bundle 插件包**。用户通过 `dsh plugin --profile <name> add dsh-gis` 安装，之后：

- 模型多出一组 `gis_*` 工具（且因为 DSH 有 PTC 模式，这些工具会自动变成 `await tools.gis_*(...)` 可编程调用）；
- 会话里出现可交互的**地图卡片**（聊天流内联），可回放、可缩放、可切换图层；
- 侧边栏多出一个 **GIS 工作台**（数据集树 + 地图 + 属性表），右侧栏多出 GIS 文件预览；
- 系统提示词里多出 GIS 领域规范，技能目录里多出 GIS 技能包；
- 现有 GIS 工具（GDAL/OGR、QGIS、DuckDB spatial、PostGIS、任意 MCP GIS 服务）被统一收敛到 `ctx.gis` 服务后面。

**四条主线对应四个技术支点**（均已核实存在）：

| 诉求 | 支点 | API |
|---|---|---|
| 更懂 GIS | 系统提示词注入 + 内置技能 + 结构化工具返回 | `ctx.systemPrompt.section()`、`ctx.skills.register()` |
| 展示 GIS 数据 | 工具卡片插槽 + 回放安全的 `presentationMeta` | `tool.call.toolview`（按工具名 keyed）、`output.presentationMeta()` |
| 浏览 GIS 数据 | 主面板 + 侧栏图标 + 右栏标签页 + 文档预览 | `main`、`sidebar.panellist`、`sidebar.right.pane.tab`、`sidebar.right.tab.document` |
| 调用 GIS 工具 | 宿主工具注册 + 受控外部进程 + MCP | `ctx.tools.register(defineTool())`、`ctx.sandbox.confine` + `ctx.subprocess.spawn`、`@deepseek-ai/dsh-mcp-client` |

**五条设计主线**（上表是四条原始需求，这里是全部五条落地主线）：

| 诉求 | 方案 | 关键 API |
|---|---|---|
| 不发布地图服务也能预览大数据 | 按需取数：COG + Range 路由、PMTiles / FlatGeobuf、概览金字塔、派生数据 LRU 缓存 | 自建 `GET /api/gis/blob?id=`（206 语义，见 3.5 路由总表） |
| 以开源 GIS 工具为主（GDAL / QGIS） | Provider 化 + 发现链（显式路径 → 已知位置 → PATH）+ 真实探测（`--version`） | `ctx.subprocess.spawn({ argv, env })` |
| 设置页配路径与环境变量，不依赖系统变量 | `.volatile()` 数据面 + 手写设置卡片；`env` 字符串注入、`undefined` 墓碑 | `ctx.settings` + `ctx.configForms` + `subprocess.env` |
| **五种必需格式：WKT / SHP / GeoJSON / GDB / PostGIS** | 数据集 ≠ 文件（单文件 / 文件族 / 目录容器 / 连接 四态）+ 有 GDAL / 无 GDAL 两档能力矩阵 | 见第七章 |
| **OGC 地图服务：WMS / WMTS / WFS 的浏览与使用** | 只做**客户端 + 本地适配层**（不发布服务）；一律走宿主代理（CORS + 凭证 + 缓存）；轴序与 SSRF 是两个必修课 | 见第九章 |

**两个必须先接受的事实**（否则会返工）：

1. **外部仓库的浏览器半必须自己复刻构建产物格式。** DSH 客户端插件的 `./client` 产物是私有 lazy-CJS 工厂（`window.__ModuleLoader__.load({id, factory})`），而官方的 `clientBundle` tsdown 预设位于 `packages/client/tsdown.client.ts`，**未随 npm 发布**（cookbook 原文：「a package outside this repository reproduces that build itself」）。这是本方案最大的工程风险，路线图里安排为第 0 步 spike。
2. **DSH 内核处于 alpha**（checkout 内包版本 `0.1.7-alpha.1`）。所有 `@deepseek-ai/*` 依赖必须锁定版本并在 `engines.dsh` 声明兼容范围。

**推荐的最小可用切片**：先做「宿主工具 + 服务端渲染出图 + 走 `present` 展示 + **一张最小的设置卡片**」。前三项不写任何客户端代码就能让模型看懂 GIS 数据；**但设置卡片是客户端工件、不能省**（见第十一节的纠正），因此它和第 0 步 spike 绑在一起。

## 三、DSH 扩展点地图（已核实）

### 3.1 插件与打包

一个插件就是一个 TypeScript 模块，导出 `apply(ctx, config)`：

```ts
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'

export const name = 'my-gis-plugin'
export const inject = ['tools']          // 依赖服务，Cordis 会等待其就绪
export interface Config { gdalBinDir: string }
export const Config: Schema<Config> = Schema.object({
  gdalBinDir: Schema.string().default(''),
})
export function apply(ctx: Context, config: Config) { /* 注册能力 */ }
```

- 注册即副作用：`ctx` 上注册的东西在插件卸载时**自动清理**；需要显式清理的资源用 `ctx.effect(() => disposer)`。
- 配置改动的 HMR 是"卸载旧实例 + 加载新实例"，所以不要依赖模块级可变状态。
- 参考：`docs/user/develop/basic/index.md`、`basic/config.md`。

**分发单元是 bundle**：

- 包的 `package.json` 声明 `"dsh": { "bundle": { "patch": "./cordis.patch.yml" } }`；
- `cordis.patch.yml` 是 YAML 数组，用 `- insert: [{ id, name, config }]` 把插件行插进 Loader；
- 安装 `dsh plugin --profile gis add dsh-gis`；验证 `dsh --profile gis --dump-config`；启动 `dsh --profile gis`。
- 加载顺序：各 bundle patch（按 profile 的 `bundles` 顺序）→ profile 自己的 `cordis.patch.yml` → `$DSH_HOME/cordis.patch.yml` → 命令行 `--patch`。**后层按 row id 覆盖前层，且是整块替换 `config` 而非深合并**。
- 本地开发用 `dsh web --patch ./dev.patch.yml`。
- 参考：`docs/user/develop/basic/publish.md`。

**外部仓库必须照做的四条打包纪律**：

1. **DSH 包要同时写进 `peerDependencies` 和 `devDependencies`**（同一版本范围）。这样运行时才会用 dsh 安装自带的**同一份实例**（Cordis 单实例，服务注入才成立）；`devDependencies` 那份只服务你的类型检查与独立测试。有状态的第三方库、dsh 的无状态工具函数放 `dependencies`。
2. **`Schemastery` 放 `dependencies`**；`Cordis` 与 `@deepseek-ai/dsh-*` 放 `peers + devDeps`。
3. **git 安装路径必须有自包含的 `prepare` 脚本**（见第十六节）。
4. **`run_code` 是保留工具名**，注册时会校验失败，别撞。

### 3.4 客户端拿到数据的契约（**设计的地基**）

卡片组件拿到的 `block` 类型是（`packages/client/ui-conversation/src/client/contract/records.ts:155,276`）：

```ts
type ToolCallBlock = RunningToolCall | ToolResultNode

interface RunningToolCall {
  callId: string; parentCallId?: string
  name: string
  argsRaw: string          // 注意：参数是 JSON 字符串
  turn: number; step: number; time: number
  subCalls: readonly ToolCallBlock[]
}

interface ToolResultNode {
  kind: 'tool-result'; seq: number; time: number; callId: string
  parentCallId?: string                             // PTC 子调用的父调用
  call: { name: string; argsRaw: string } | null   // 窗口截断时可能为 null
  callTime: number | null                           // 配对 tool/call 的时间，用于调用行时长
  content: readonly ContentBlock[]
  isError: boolean
  error?: { name: string; code: string; reason?: string }
  meta?: unknown            // ← 持久化的 presentationMeta 落在这里
  subCalls: readonly ToolCallBlock[]
}
```

三条硬性设计约束（出自 `docs/cookbook/adding-a-tool.md`）：

1. **卡片必须是纯投影**：Web 卡片是 `tool.call.toolview` 组件，它在**实时流式**和**会话日志回放**两种情况下渲染，所以禁止 I/O、禁止读会话状态、禁止时钟/随机。
   > **更正**：这条约束此前挂在 `presentCall` / `presentResult` 名下。cookbook 原文是「**The built-in Web Client does not consume `presentCall` or `presentResult`**」——**这两个宿主方法在内置 Web 客户端里根本不跑**。纯净性纪律对 `tool.call.toolview` 同样成立，但**不要为 `presentCall` / `presentResult` 投入实现**（它们只服务其它消费 `card` 渲染意图的 UI）。
2. **UI 专用数据不进模型结果**：模型看的是 `output.render()` 的 prose；UI 要的结构化事实放 `output.presentationMeta(args, value)`，它会被持久化到 `tool/result` 的 `meta` 上，从而回放可复现。
3. **必须容忍坏数据**：`defineTool` 对展示路径是软校验——参数畸形时返回 `undefined` 走通用卡片兜底，**不允许抛异常**。另外 `call` 可能为 `null`，卡片要能只显示 `callId`。

### 3.5 数据通道的四种形态（选型建议）

宿主已经提供了四条把数据送到浏览器的路，**不要新造第五条**：

| 形态 | 机制 | 适用 | 依据 |
|---|---|---|---|
| 复用宿主文件路由 | 鉴权栅栏内的 `GET/HEAD /api/file?path=<绝对路径>`：走 `ctx.fs` 读、`mime-types` 定 Content-Type、`Cache-Control: private, no-store`、`X-Content-Type-Options: nosniff`、`CSP: sandbox; default-src none`，超限 413 | **小文件的整文件字节**——`/api/file` **只做整文件 GET/HEAD、没有 Range**，所以**不能**用于 COG / PMTiles | `packages/api/session-controller/src/media-references.ts:66-76` |
| 自建 fetch 路由 | `ctx.connection.fetch.register({ path, methods, requestBody, fetch })` | **派生态**：见下方路由总表（**exact path + query**，不支持路径段参数） | `packages/client/ui-deliverables/src/present-open.ts:20-46` |
| 类型化 RPC | 宿主 `extends TypertRemoteService` + `@Remote({ mode: 'stream' })`；客户端 `ctx.remote.$mount()/$stream()/$on()`。一元调用返回 `RemoteResult<T> = {ok:true,value}` 或 `{ok:false,error}`，**载体故障不 reject** | **数据集目录、图层状态、长任务进度** | `packages/typert/protocol/src/index.ts:166-257`、`packages/api/gateway` |
| 客户端资源协议 | `dsh-resource://<type>/...` 注册 Provider + `useResource` hook | **实时图层/地图状态**在 React 树里响应式订阅 | `packages/client/resources/README.md:41-58` |

**⚠️ 硬约束：`ctx.connection.fetch.register` 只做 exact pathname 匹配。**

`ConnectionFetchRoute` 的注释原文是「One **exact**, transport-independent Fetch route」（`packages/client/connection/src/rpc.ts:143-153`）；匹配是对 pathname 做 Map 精确查找（`rpc-host.ts:135,140`），同路径重复注册直接抛错（`rpc-host.ts:163-165`）。宿主自己的流式路由也全是「字面常量 + 查询参数」（如 `/api/present.open?sessionId=&seq=&index=`）。

**结论：任何形如 `/api/gis/tile/<z>/<x>/<y>` 的路径段参数路由永远不会命中。** 全部改为 exact path + query。

**插件路由总表（唯一权威，其余章节一律引用此表）**：

| 路由（exact path） | 方法 | 用途 | 参数 |
|---|---|---|---|
| `/api/gis/blob` | GET / HEAD | 单个数据集字节，**支持 Range**（`Accept-Ranges` / `206` / `Content-Range`） | `?id=<datasetId>`；COG / PMTiles / FlatGeobuf 走这条 |
| `/api/gis/geojson` | GET | 按 bbox 取简化后的 GeoJSON | `?id=&layer=&bbox=&limit=&simplify=` |
| `/api/gis/tile` | GET | 瓦片：本地 MVT 或远端 WMTS / WMS 适配 | `?src=<datasetId\|serviceId>&z=&x=&y=` |
| `/api/gis/features` | GET | WFS / PostGIS 要素（分页） | `?service=&type=&bbox=&count=&startIndex=` |
| `/api/gis/catalog` | GET | 数据集与服务清单（客户端目录树用） | 也可走类型化 RPC |

全部注册在 `ctx.connection.fetch` 的**鉴权栅栏内**，且**只接受不透明 id**，不接受任何路径参数。

实践建议：小文件的整文件字节可以直接复用 `/api/file`（省掉一套自研路由与它的安全面）；**需要 Range 或派生态一律走上面的表**；目录与状态走类型化 RPC。

### 3.6 生命周期与 HMR 的两个坑

- **异步 disposer 是并发的。** 卸载时 disposer 按注册**逆序开始**，但多个异步 disposer **并发执行、没有串行完成保证**。有顺序依赖的清理必须写进**同一个 `ctx.effect()`** 返回的单个 disposer 里（`docs/user/develop/framework/index.md`）。GIS 插件同时持有进程句柄、路由、数据集注册表，最容易踩这个。
- **不要用模块级可变状态。** 改源码或 `cordis.patch.yml` 会走「卸载旧实例 + 加载新实例」，状态必须由新的 `apply` 重建。每个注册表都要配一个 HMR 安全测试：dispose 掉贡献 fiber，断言注册被完整清理（`docs/testing.md:9`）。
- 顺带排除一个误解：`packages/extensions/cordis-host-runner`（让 agent 在 `node:vm` 里现写现跑 Cordis 包）**不是分发路径**——那些定义是会话级、进程内的，重启即消失，且需审批。

### 3.7 客户端半的硬约束清单（外部仓库必读）

> **配套文档：[运行时契约（实测汇总）](./运行时契约.md)。** 本节只列客户端半；那份文档汇总了 M0/M1a/M1b 三轮实测发现的 **17 条契约陷阱**，覆盖宿主服务、客户端半、设置与 Plugins 页、数据格式四层，并给出每一条「类型怎么说 vs 运行时怎样」。
>
> **共同形态**：全部**编译期不报错、单元测试发现不了、且几乎全是静默失败**。实现本项目任何新组件前，先读那一份。

1. **两条通道互斥**：动态 module-table 插件（`dsh.client` + `./client` 导出）vs 静态链接客户端库（`staticLinked`，无 `dsh.client`，由 apps/web 的 Vite 直接链进 shell）。**第三方只能用前者**。
2. **跨插件 value import 是构建错误。** 有一道**构建期 bundle 纯净度门禁**（bundle purity gate，`tsdown.client.ts:528-546`——与「纯函数」无关，此前译错）会拒绝任何「既不在模块表白名单、也不属于 inline-safe 线层、也不是 vendored library 或生成的 `/remote` 贡献」的 `@deepseek-ai` **value** 导入，报错原文是 cross-plugin value imports are forbidden。**对其他 client 包只能 `import type`**，运行时协作一律走 Cordis 服务。
3. **产物是经典脚本，不是 ES module**：注册 `window.__ModuleLoader__.load({ id, factory })`，由 `/plugins/<pkg>/client.js?rev=<hex>` 提供，多插件合并形态是 `/plugins/??a/client.js,b/client.js&rev=`；`rev` 由 mtime/ctime/size 算出，响应 `immutable` 缓存一年。**没有 import map。**
4. **`dsh.client.inject` 不是 Cordis 服务注入**——它是「包名依赖边」，只决定 factory 到达顺序与组合；真正的服务注入写在插件的 `inject` 导出里。
5. **React 必须与 shell 同版本**（当前 `^18.2.0`），否则模块表里的 `react` 实例对不上。
6. **`tool.call.toolview` 的 key 写错不会报错，只是永远不渲染**（keyDomain 原文：a typo never renders）。
7. **不要注册进 `root`**：那是单槽，会遮蔽整个框架——页面只剩你的组件，框架声明的所有座位全部消失（`registry.ts:34-44`）。要浮层用 `shell.overlay`。
8. **样式只能用 `--dsw-alias-*` token**，组件尽量复用 `packages/client/ui-primitives`（Button/Tag/SegmentedTabs/Menu/Modal/HoverCard/Toast/DisclosureRow/PathLabel/FileTypeIcon/JsonTree/CodeBlock 等）与 `ui-dockkit` 的停靠几何。**不要硬编码颜色**——token 层已按明暗主题解析好。
10. **🔴 eager 与 lazy 图之间不得共享任何模块。** 若 eager 组件与 `import()` 懒加载组件**共享**一个模块（最容易发生的是共享同一份 CSS Module），rolldown 会把它提升为共享 chunk，入口于是出现 `require("./client.xxx.js")` —— **同步 require**，而加载器协议明确禁止「entry 与 chunk 之间同步 require」。修法是让两个图各自持有自己的样式/工具模块。**这条只有构建时才会暴露**（M0 实测踩到，见附录 I）。

11. **`clientBundle` 必须同时产出 node 半。** 客户端包的 Loader 行按**裸包名**解析到 `lib/index.js`；若只产出浏览器半，加载时会直接报 **`failed to import`**（M0 实测）。DSH 的 `clientBundle()` 同时产出两半正是为此。宿主半即使 `apply` 为空，也必须是一个真实产物。
12. **客户端代码的类型检查需要「声明该插槽的那个包」。** `ctx.slots` / `ctx.locale` 不在裸 `Context` 上，是客户端包声明合并来的；且**必须 import 声明该插槽的包**，key 才进 `SlotMap`（`tool.call.toolview` 需 `dsh-client-ui-tool/client`，`ctx.slots` 需 `dsh-client-ui-renderer/client`）；自己的 locale 命名空间要 `declare module '@deepseek-ai/dsh-client-ui-slots'` 合并 `LocaleNamespaceMap`。**另注意 `dsh-client-ui-slots` 只有 `.` 导出、没有 `/client` 子路径**——照抄仓内写法会报模块找不到。
13. **HMR 的边界**：宿主用 **stat-poll**（默认 500ms）盯着自己服务的 bundle，所以**任何进程**改写 `lib/client.js` 都会触发免刷新重载——外部仓库跑自己的 `tsdown --watch` 就够，不需要 DSH 仓库的 `pnpm run dev:web`（那个脚本只发现仓库内的 `packages/<group>/<name>`）。但改 Web shell 或宿主侧仍需重新构建 + 刷新页面；**dev 循环运行期间新加的插件行要重启**。

> **降低第 0 步风险的捷径**：宿主仓库里有两个**手写、无构建步骤**的客户端插件样例——`apps/web/tests/fixtures/plugins/fixture-input-extension/client.js`（46 行：三个槽注册 + 一份字典）和 `fixture-live-client/client.js`（109 行：自注入样式、`shell.overlay`、会话右键菜单项，以及证明 HMR 生命周期的挂载/销毁计数器）。**先照抄一个手写的 `client.js` 把格式验证通，再决定要不要复刻 tsdown 预设**——这能把最大风险的验证成本压到最低。

> **关于文档（此前说过头了，在此更正）**：`docs/user/develop/` 确实没有客户端 UI 插件的**教程**，但**参考文档是齐的**——`packages/client/modules/README.md`（讲清 lazy-CJS、boot graph、`require.async` 兄弟 chunk、combo URL、HMR）、`docs/subsystems/client-modules.md`、`packages/client/AGENTS.md`、`docs/cookbook/adding-a-settings-card.md`（含宿主提供的 `form.state` / `form.mutate`）都在。**真正缺的只有那份未随 npm 发布的 `clientBundle` 预设文件**（它 import 了三个仓库内模块）。所以客户端工期要按「**复刻 preset + 替换 4 处仓库内 import + 跟进上游漂移**」估，而不是按「从零读源码」估。
>
> 另外更正一点（此前说「没有任何 canvas 代码」，不准确）：**DSH 没有 WebGL / 地图渲染层**，`browser-use` 与 `computer-use` 也只是宿主侧的 Provider 注册表、没有 UI；唯一的 `<canvas>` 用法是 PDF 预览的页面栅格（`ui-sidebar-documentpreview/src/client/pdf/pdf.tsx:175` + `pdf/runtime.ts`）。所以**没有现成的画布层可以当地图底座复用**——最接近的先例是 Worker 里的 PDF.js 与手势组件 `ZoomViewport.tsx`。

**分层原则**（照搬 DSH 自己的 capability layering 实践，见 `docs/user/develop/practice/index.md`）：

- `gis-core` = **Service Definition**：只定义数据模型、错误码、Provider 接口（`ctx.gis`），不实现任何引擎。
- `gis-<engine>` = **Service Provider**：实现同一个接口；可同时挂多个，按能力路由与降级。
- `tool-gis-*` / `ui-gis` = **Consumer**：只依赖 `ctx.gis` 门面，不直接调 `ogr2ogr`。

这样"用户装没装 GDAL"就变成一个可降级的运行时事实，而不是一堵墙。

## 六、能力设计

### 6.1 「更懂 GIS」：知识注入

三个层次，从软到硬：

**(a) 系统提示词分节** —— 注入**纪律**而不是百科：

```ts
ctx.systemPrompt.section({
  name: 'gis:discipline',
  order: 5000,                       // 外部插件可用任意有限 order
  text: [
    'GIS 数据在未声明坐标系时应先确认，禁止臆测 CRS。',
    '所有面向展示与模型输出的坐标一律使用 EPSG:4326（经度,纬度），',
    '并在返回值中显式标注坐标系；需要投影计算时调用 gis_crs，不要手算。',
    '面积/长度计算必须使用等积/等距投影或明确说明近似误差。',
    '读取 .shp/.gpkg/.tif 等二进制 GIS 格式时不要用 read，改用 gis_inspect。',
    '大图层不要整表读取：先用 gis_inspect 看要素数与范围，再用 gis_query 带 bbox/limit 取子集。',
  ].join('\n'),
})
```

**(b) 内置技能** —— 通过 `ctx.skills.register()` 注册**内存技能**（Provider 默认标签 `runtime`，无需落盘）。字段名是 **`content`**（不是 `body`），调用策略放在 `invocation` 里：

```ts
ctx.skills.register({
  name: 'gis-crs-troubleshooting',                            // kebab-case，必填
  description: '诊断坐标系缺失、错配与偏移',                     // 必填，用于路由
  whenToUse: '数据缺少 .prj 或 CRS 明显错配时',
  content: '...Markdown 正文...',
  source: 'runtime',          // **必填**（SkillSummary.source）——仓内调用一律显式传
  invocation: { modelInvocable: true, userInvocable: true },   // 省略即两者皆可
})
```

建议技能包：`gis-format-conversion`（格式选择与转换）、`gis-crs-troubleshooting`、`gis-data-quality`（几何有效性/拓扑/空几何）、`gis-web-map-publishing`（XYZ/MVT/COG 发布）、`gis-spatial-analysis-recipes`。

要**随包分发整套技能**（而不是逐个内存注册），用 `ctx.skills.registerProvider()` 提供 `source: 'bundled'` + `resourceBase` 的 Provider——仓内参考实现是 `packages/skill/skill-badge`。用户侧也可直接放到 `.dsh/skills/<name>/SKILL.md`（发现优先级：`.dsh/skills` 100 → `.agents/skills` 200 → 自定义目录 300 → `$DSH_HOME/skills` 400 → `<agentsHome>/skills` **500** → bundled 600（**需配置 `bundledSkillDir`**））。

**(c) 结构化工具返回** —— 这是最硬的一层：让模型拿到**数字和枚举**，而不是让它解析 prose。`gis_inspect` 返回真实的 `featureCount`、`bbox`、`epsg`、字段类型、几何有效性问题清单，模型据此推理才不会瞎编。

### 6.2 「用工具」：工具契约

统一命名前缀 `gis_`（与内核的 `cordis_*` 惯例一致）。每个工具的 `output.schema` 都按「程序可用的 API」来设计（cookbook 原话：Design `output.schema` as a useful programmatic API），因为 PTC 模式下模型会直接 `await tools.gis_query({...})` 做组合。

> **名称与参数的唯一权威是附录 A**；下表只保留本节关心的**规范值（canonical value）设计**，不重复工具签名。

| 工具 | 作用 | `output.schema` 要点 |
|---|---|---|
| `gis_inspect` | 数据集体检：格式/驱动、CRS、几何类型、要素数、范围、字段模式、几何有效性 | `{ path, driver, layer, crs: { epsg, name, wkt }, geometryType, featureCount, bbox: [w,s,e,n], fields: [{name,type}], issues: [{code,message,count}] }` |
| `gis_catalog` | 扫描工作区，登记可识别数据集，产出稳定 id | `{ root, datasets: [{ id, path, driver, kind }], skipped: [{path,reason}] }` |
| `gis_query` | 属性/空间查询（WHERE / bbox / limit / 字段投影） | `{ columns, rows, rowCount, truncated, bboxUsed }` |
| `gis_convert` | 格式转换、重投影、裁剪、子集导出 | `{ output, driver, crs, featureCount, bytes }` |
| `gis_render` | 渲染预览图 / 生成图层切片描述 | `{ mapId, bbox, layers: [...], image?: {path,width,height}, stats }` |
| `gis_crs` | CRS 描述 **+ 点/几何换算**（合并了原 `gis_crs_describe` 与 `gis_transform_point`） | `describe` → `{ epsg, name, unit, axis, areaOfUse }`；`transform` → `{ from, to, input, output }` |
| `gis_capabilities` | 运行时能力自述（模型第一轮就能问「本机能做什么」） | `{ providers, gdal?, qgis?, drivers, formats, connections }` |
| `gis_env` | 回显解析后的环境与将执行的命令（不得不用 shell 时的兜底） | `{ env, prefix, resolvedBins }` |

工具实现要点：

- **后台化**：`gis_convert` / `gis_render` 这类可能跑几十秒的，用配置开关 gate 后走 `ctx.jobs.start({ kind, label, owner: exec.agent.id, run })`，成功分支返回 `{ kind: 'background', jobId }` 这种类型化句柄（cookbook 明确要求：PTC 模式绝不能靠解析 prose 拿 jobId）。
- **取消**：前台工作必须遵守 `exec.signal`。
- **不自己造策略**：不要在工具里硬编码"允不允许写文件"，交给 `tools/pre-execute` 钩子，让部署方决定。
- **`presentationMeta`**：`gis_render` 用它投影出可回放的地图描述（见下）。

### 6.3 「展示 GIS 数据」：地图卡片

**核心机制**：工具卡片是**纯投影**，字节通过 HTTP 路由按需取。

`gis_render` 的 `output.presentationMeta` 产出**有界、可回放、不含字节**的地图描述：

```ts
presentationMeta(args, value) {
  return {
    mapId: value.mapId,
    bbox: value.bbox,                                  // [w,s,e,n] EPSG:4326
    layers: value.layers.map(l => ({
      id: l.id,
      kind: l.kind,                                    // 'geojson' | 'raster' | 'mvt'
      url: '/api/gis/blob?id=' + l.datasetId,   // 只放路由，不放数据（路由总表见 3.5）
      style: l.style,
    })),
    basemap: 'none',
  }
}
```

客户端半注册 `tool.call.toolview` 的 `gis_render` 键，从 `block` 里取值：

- 运行中（`RunningToolCall`）：解析 `argsRaw` 显示"正在渲染 …"占位；
- 已结算（`ToolResultNode`）：读 `meta` 拿地图描述 → MapLibre 初始化 → 按 `layers[].url` 拉 GeoJSON/MVT；
- `isError` → 显示诊断；`call === null` → 退化成只显示 `callId` 的通用行。

**这条设计同时解决了三个问题**：会话回放可复现（数据在 `meta` 里）、会话日志不被二进制污染、大图层按需加载。

**另一种零客户端方案**（第一阶段就用它）：`gis_render` 在服务端把图渲染成 PNG，写进工作区，然后调用 `present` 工具交付。这样完全复用宿主已有的图片附件链路与 `present` 卡片，UI 零开发量。

**不要动 `present` 的 toolview**：`present` 这个键已经被 `client-ui-deliverables` 的 `PresentRow` 占用，注册会**替换**宿主的交付卡片。要扩展请用 `deliverables.file.actions`。

### 6.4 「浏览 GIS 数据」：GIS 工作台

三层递进，每层都可以独立上线：

**L1 文件预览（改动最小，而且不用自己发明注册机制）**

宿主已有**按扩展名分派的文档预览注册表**（`packages/client/ui-sidebar-documentpreview/src/client/document/registry.ts:9-28`）：

```ts
export interface DocumentPreviewDefinition {
  readonly id: string
  readonly extensions: readonly string[]
  readonly binaryExtensions?: readonly string[]
  readonly priority?: 'builtin' | 'extension'
  readonly title: () => string
  readonly loading: DocumentLoadMode
  readonly wrap?: boolean
}
```

匹配顺序是**外部 `'extension'` 档优先 → 最长后缀 → 注册顺序**，所以插件能干净地接管 `.geojson/.fgb/.tif/.gpkg` 而不碰宿主已有实现。预览体收到的 `DocumentContent` 是 `{kind:'text'|'bytes'|'renderer'}` 三态（`document/contract.ts:17-30`；33-46 是另一个接口 `DocumentBodyOwner`），可以用 `loading:'bytes-complete'` 直接拿字节，也可以 renderer 自取。

**接入要两次注册，缺一不可**（definition 的 `id` 就是槽的 key）：

```ts
export const inject = ['slots', 'locale', 'documentPreviews', 'remote', 'remote.workspaceFiles']

ctx.effect(() => ctx.documentPreviews.register({
  id: GEO_ID,
  extensions: ['geojson', 'topojson', 'kml', 'gpx', 'wkt', 'shp', 'gpkg', 'fgb', 'pmtiles', 'tif', 'tiff', 'cog'],
  binaryExtensions: ['shp', 'gpkg', 'fgb', 'pmtiles', 'tif', 'tiff', 'cog'],
  priority: 'extension',     // 压过内置 text/code 预览，否则 .json/.txt 会被它们先认领
  title: () => t('title'),
  loading: 'renderer',       // 大栅格必须自取，见下
  wrap: false,
}), 'ui-gis: preview metadata')

ctx.effect(() => ctx.slots.inject('sidebar.right.tab.document', () => ctx.slots.register({
  name: 'sidebar.right.tab.document', key: GEO_ID, locale: NS,
}, GeoJsonBody)), 'ui-gis: preview body')
```

- 小文本格式（GeoJSON/KML/WKT）用 `loading: 'text-pages'`；小二进制用 `'bytes-complete'`；**大栅格必须 `'renderer'`**。
- **字节取数分主备两条路**（详见第八章）：**主路径是插件自己的 Range 路由** `GET /api/gis/blob?id=<datasetId>`（206 语义），`geotiff.js` / `pmtiles` 会自己发 Range 请求；**兜底**才用 `ctx.remote.workspaceFiles.readBytes(...)`——它默认**单窗口 2 MiB、整文件 32 MiB、文本 5000 行**，且**超限是拒绝、不是截断**（`packages/api/workspace-files/src/index.ts:79-80,186-191`），每次一个 RPC 往返，不适合连续 Range。
- 无论走哪条路，栅格解码都要放进 **Web Worker**——这正是宿主 PDF/Excel 预览的做法（`ui-sidebar-documentpreview/src/client/pdf/runtime.ts`、`excel/worker.ts`）。**绝不要把整个栅格读进内存。**
- 平移/缩放直接抄 `ui-sidebar-documentpreview/src/client/zoom/ZoomViewport.tsx`（指针锚定、fit-width、手势收敛，212 行）。
- `sidebar.right.tab.document.unpreviewable` 注册「用 GIS 查看器打开」兜底；`sidebar.right.tab.document.actions` 注册「导出为 GeoJSON / 导出 PNG」。

**L2 右栏图层面板**
- `sidebar.right.pane.tab` 注册新标签类型 `gis-layers`：图层可见性、符号、透明度、缩放到图层、属性表。
- 用 `ctx.sidebarRight.openResource(address, { params })` 打开（照 `ui-deliverables` 的用法）。

**L3 主面板工作台 + 会话地图视图**
一个主面板页需要**三件事**：`sidebar.panellist` 注册图标行（`{ id, order, label }`）、`main` 注册同 id 的面板体、再用 **`ctx.layout.selectPanel(id)`** 真正切过去（`packages/client/ui-layout/src/client/service.ts:16-52`）。

- `sidebar.panellist` 注册 id `gis` + `main` 注册 key `gis`：全屏地图 + 左侧数据集树 + 底部属性表 + 工具条（导入、导出、样式、底图）。
- `conversation.view` 注册 `gis`：把当前会话所有 `gis_render` 结果聚合成一张图，跟着对话走。
- 可选 `shell.overlay` 做真·全屏地图。

**数据集注册表（宿主侧，`gis-core` 拥有）**：所有可浏览的数据集都要有一个**不透明 id**，映射到工作区内（或明确授权范围内）的真实路径。客户端只认 id，不认路径——这样既避免把文件系统结构暴露给页面，也让路由可以做白名单校验（见第十二节）。

### 6.5 客户端地图状态的共享约定

聊天卡片与工作台看的是同一份地图，必须约定谁拥有它，否则会出现「卡片里切了图层、工作台没变」：

- **唯一事实来源在宿主**：图层、可见性、范围、样式属于**会话级**状态，落 `ctx.sessionProjections.register({ key: 'gis/map', stateSchema, init, apply, wire, stateVersion: 1 })`，由 `exec.agent.session.append('gis/layer', ...)` 的事件驱动——这样**回放与恢复天然一致**；
- **客户端不各存一份**：卡片与工作台都读同一份 projection 的 `wire` 视图，通过同一个资源地址（`dsh-resource://gis/map`）订阅（`useResource` 在每个插槽组件上都可用）；
- **纯展示偏好留本地**（底图开关、面板宽度）——它们不该污染可回放的会话日志；
- **判断标准**：影响「模型看到的图」或「回放后的结果」的，必须进 projection；只影响「我现在怎么看」的，留本地。

### 6.6 数据集 id 的生命周期与回放语义

「回放可复现」这条验收（第十三章第二阶段）建立在一个**容易被忽略的前提**上：卡片 `meta` 里放的是路由，路由要能解析出 id，而 id 必须**在重启后仍指向同一个数据集**。如果注册表只是进程内内存，重启或换会话后回放出来的地图就是一堆 404。

1. **id 由内容稳定派生**，不是自增序号：`id = 'ds_' + sha256(规范化绝对路径 + 文件族成员 + size + mtime)` 取前 16 位。同一份数据重复扫描得到同一个 id；源文件变了就得到新 id，旧 id 自然失效——**这正是要的语义**；
2. **登记落 `ctx.storageDomain`**（`defineDomain({ name: 'gis', version, tables: { datasets, services } })`），与 OGC 服务定义同一处，重启后仍可按 id 解析；
3. **解析失败的兜底**：id 查不到（文件被移走/删除）时路由返回 **404 + 结构化原因**，卡片渲染成「数据已不可用」的降级态，而不是空白或崩溃——**回放绝不能抛异常**；
4. **连接类数据集**（PostGIS、OGC 服务）的 id 由「连接剖面名 + 图层名」派生，不掺路径；
5. **登记与缓存分离**：派生缓存按 id 分目录、可整体删除重建；**登记表必须持久化**（重建会换 id），缓存不必。

## 七、数据格式支持（WKT / SHP / GeoJSON / GDB / PostGIS）

这一章把五种必需格式的**真实形状**讲清楚——因为它们的形态完全不同，直接决定了数据集模型、降级行为和工具契约。

### 7.1 前提抽象：数据集 ≠ 文件

五种格式有四种**形态**，所以数据集注册表不能是「id → 路径」，必须是可辨识联合：

| 形态 | 例子 | 注册表要存什么 |
|---|---|---|
| 单文件 | `.geojson` / `.wkt` / `.csv` | 路径 |
| **文件族** | `.shp` + `.shx` + `.dbf` + `.prj` + `.cpg` | 主文件 + **兄弟文件集合**（移动/复制/导出必须整族一起） |
| **目录容器** | `x.gdb`（内含多个要素类） | 目录路径 + **图层列表**（一个数据集 → 多个 layer） |
| **连接** | PostGIS | 连接描述（host/port/db/user/schema）+ **凭证引用**（不含密码） |

这一条会渗透到所有工具：`gis_inspect` 必须能返回多图层，`gis_convert` 必须能选层，数据集 id 必须能指向文件族或连接而不是一个路径。

### 7.2 WKT —— 模型最该用的交换格式

**先分清两种完全不同的 WKT**，混在一起会出大错：

- **几何 WKT**：`POINT(116.4 39.9)`、`POLYGON((...))`、`GEOMETRYCOLLECTION(...)`；
- **坐标系 WKT**：`GEOGCS[...]` / `PROJCS[...]`（`.prj` 文件与 `gdalsrsinfo` 输出的就是它）。

另外要支持 **EWKT**（PostGIS 的 `SRID=4326;POINT(...)`）与 **WKB / WKB hex**。

**为什么 WKT 很重要**：它比 GeoJSON 短得多（**省 token**），且模型本身极擅长读写。所以：

- `gis_query` 增加 `geometry: 'none' | 'wkt' | 'geojson'`，**默认 `wkt`** 并做坐标精度截断；
- 工具**接受**内联 WKT 作为输入（`gis_render` / `gis_convert` 不必先落盘）；
- 解析用 `@terraformer/wkt`（MIT 2.2.2）。

**硬规则**：裸 WKT 没有坐标系。必须显式给 `crs`，或明确报 `crs: unknown`——**绝不默认 EPSG:4326**。

### 7.3 SHP —— 从来不是一个文件，且有两个经典杀手

`.shp` 必须与 `.shx`、`.dbf` 一起读，可能还有 `.prj`、`.cpg`、`.sbn/.sbx`、`.qix`。注册、复制、导出都要**整族处理**；`.zip` 打包的 shapefile 极常见（`shpjs` 可直接读 zip）。

**杀手一：`.prj` 缺失或错误 → CRS 未知。**
策略：`.prj` 存在就解析；缺失则 `gis_inspect` 报 `crs: { source: 'unknown' }`，并**拒绝**任何依赖 CRS 的操作（面积、长度、叠加），提示用户用 `gis_convert --assume-crs EPSG:xxxx` 显式指定。**不允许猜。**

**杀手二：DBF 编码 → 中文属性表乱码。**
`.cpg` 优先；否则**必须允许显式 `encoding`**（`GBK` / `GB18030` / `UTF-8` / `BIG5`），并在设置与工具参数里都暴露。GDAL 侧对应 `-lco ENCODING=` 与 `SHAPE_ENCODING` 环境变量。**这是中文用户最容易踩的坑，必须做成显式参数而不是靠自动猜。**

其余要在工具里如实体现的约束：**2 GB 是 Esri 的实用单文件上限**（格式本身用 32 位字偏移、可到 8 GB，GDAL 实现上限 4 GB，超过 2 GB 只是「不推荐」）、字段名 10 字符、DBF 字段类型有限、Z/M 坐标。

### 7.4 GeoJSON —— 规范与现实不一致

RFC 7946 规定**必须 WGS84、且经度在前**，但现实里大量文件违反：带投影坐标、或纬度在前（GeoJSON 早期习惯）。策略：

- 读入时**检测但不擅自改写**，`gis_inspect` 报 `crs: { assumed: 'EPSG:4326', source: 'assumed-rfc7946' }` 与轴向警告；
- 坐标超出 `[-180,180] / [-90,90]` 时**判定为可疑并拒绝直接出图**，在 `issues` 里给出 `code: CRS_AMBIGUOUS` 与**原始 bbox**。注意这是**启发式**（投影后的米制坐标可能恰好落在范围内），所以它给的是「可疑 + 证据」，**不是**「断言这是投影坐标」；用户可用显式 `crs` 参数覆盖——而不是把它画到几内亚湾去；
- 支持四种根：`FeatureCollection` / `Feature` / 裸几何 / `GeometryCollection`；保留 `bbox` 与 `id`；
- **大 GeoJSON 是性能陷阱**：几十万要素的单文件很常见 → 走第八章的平铺/简化路径，**禁止整文件进上下文**；
- **NDJSON / GeoJSONSeq**（每行一个 Feature）是大数据的常见形态，要支持**流式读取**，不要一次性 parse。

### 7.5 GDB（ESRI File Geodatabase）—— 最难，且必须说清边界

它是**目录不是文件**，一个 GDB 内含**多个要素类**（还可能有表、栅格、拓扑、关系类）——这正是 7.1 里「一个数据集多个图层」的由来。

**它是专有格式、无公开文档，但 GDAL 的 OpenFileGDB 驱动能力比普遍认知强得多（此处此前写错，已更正）：**

- **读支持自 GDAL 1.11.0（2014）起内置**，无需任何外部依赖；栅格读自 3.7 起；
- **写 / 更新自 GDAL 3.6.0 起内置**，官方说法是其功能范围「与 FileGDB 驱动的写侧相同、甚至更大」；自 GDAL 3.11 起，基于 SDK 的 FileGDB 驱动把创建 / 更新**委派**给 OpenFileGDB；
- 所以「写入需要不可再分发的专有 SDK」是**过时说法**：Esri 已把 File Geodatabase API 以 **Apache-2.0** 发布在 `github.com/Esri/file-geodatabase-api`；
- **仍然存在的真实限制**：ArcGIS 9.x 的 `.gdb` 只读；SDC / CDF 压缩数据仍需 SDK；写入只产生 **v10.x** 格式。

**我们的产品选择是 GDB 只读**——**不是因为做不到，而是因为写 GDB 属于「数据编辑」，明确不在 v1 范围**（附录 E 第 3 条）。要输出请转 GPKG / SHP / GeoJSON。

- **GDB 仍是唯一没有纯 JS 兜底的格式**——没有 GDAL 就完全不可用。

因此必须做到（否则用户只会看到「打开失败」）：

1. 用 `ogrinfo --formats` 探测 **`OpenFileGDB` 是否在驱动列表里**，并记录 GDAL 版本；
2. 声明**最低 GDAL 版本要求**；
3. 缺失时给**可执行的诊断**——例如「你的 GDAL 不含 OpenFileGDB 驱动（读需 ≥ 1.11、写需 ≥ 3.6），请升级或用 QGIS 自带的 GDAL」，而不是一句失败。

补充：**Personal GDB（`.mdb`，Access 格式）** 需要 Windows 上的 MDB 驱动；**Enterprise GDB** 实际就是 PostGIS / SQL Server / Oracle——走下面那条路。图层枚举用 `ogrinfo -so <gdb>`；GDB 里常见的 Z/M、域（domain）、子类型（subtype）在 `gis_inspect` 里只报**存在性**，不展开。

### 7.6 PostGIS —— 不是文件，架构上单独对待

**连接与凭证：配置里只放引用，绝不放密码。**

```ts
import { credentialRef } from '@deepseek-ai/dsh-credentials'

const ref = credentialRef('PGPASSWORD')                  // POSIX 标识符形状，branded
const hit = await ctx.credentials.resolve(ref)           // { value, source } | undefined
const info = await ctx.credentials.describe(ref)         // { configured, source?, writable } —— 永远没有 value
```

- 密码走 `credentialRef('PGPASSWORD')`：**每次操作解析、不缓存**，所以**轮换密钥不用重启**；
- 整条连接剖面走 `credentialKey('dsh-gis', 'postgis-prod')` + `modifyRecord`（唯一的写路径：读-决策-替换，带排他）；
- 设置页用 `describe()` 显示**「已配置 / 来源 / 是否可写」，永远拿不到值**——这正是连接 UI 需要的。

**SQL 安全是硬要求（这是本项目最大的注入面）：**

- **一律参数化查询**，绝不把模型输出拼进 SQL 字符串；
- 标识符（表名/列名/模式名）**无法参数化** → 必须先对着 `information_schema` / `geometry_columns` **白名单校验**再拼接；
- **默认只读**：会话设 `default_transaction_read_only = on`；写操作必须显式开启且走审批；
- **必须设 `statement_timeout`**（建议 30s）与 `idle_in_transaction_session_timeout`——否则一条慢查询能把会话和连接池一起拖死；
- 收窄 `search_path`，只暴露允许的 schema。

**元数据要便宜——不要用 `count(*)` 全表扫：**

- `geometry_columns` / `geography_columns` 拿图层、几何类型、SRID、维度；
- `ST_EstimatedExtent(schema, table, geom_col)` 拿范围（**走统计信息，通常远快于 `ST_Extent`**）——但它**在无统计信息时返回 NULL**（空表或没跑过 `ANALYZE`），且**只有约 95% 的准确度**，**绝不能当作精确 bbox 展示**；
- `reltuples` 拿估算行数；用户显式要精确值时才真算。

**大表取数全部推到服务端：**

- **瓦片优先用 PostGIS 原生 MVT**（需 **PostGIS ≥ 2.4**）：`ST_AsMVTGeom` + `ST_AsMVT` **直接在数据库里生成 MVT，连 GDAL 都不需要**——这是 PostGIS 最优雅的路径，也是它相比文件的天然优势；
  - 用 **`ST_TileEnvelope`**（PostGIS 3.0+）造瓦片范围，并以**索引友好的 `geom && ST_TileEnvelope(...)` 预过滤**，不要先算再过滤；
  - `ST_AsMVTGeom` **要求几何已经在瓦片 CRS**（先 `ST_Transform`），且不支持 JSON 属性；
- 窗口读取：`ST_Intersects(geom, ST_MakeEnvelope(..., srid))` + `LIMIT`；
- 抽稀：`ST_Simplify` / `ST_SimplifyPreserveTopology`；
- 属性表分页：`LIMIT/OFFSET` + **稳定 `ORDER BY`（优先主键）**，并回 `truncated`。

**实现选择**：`pg`（MIT）直连做目录/元数据/查询；**同时**保留 GDAL 的 PG 驱动（`ogr2ogr PG:"..."`）用于重型格式转换——两者共用同一份连接参数与凭证引用。

**还要处理的现实**：几何列可能是 `geography` 而非 `geometry`；SRID 可能是 `0`（未知）；表可能**没有主键**（分页会不稳，必须告知）。

**注意**：沙箱**不覆盖网络**（见第十二章第 8 条）——出网策略、连接白名单、超时全都要自己管。

### 7.7 能力矩阵：有 GDAL / 没有 GDAL

| 格式 | 读（有 GDAL） | 读（无 GDAL，纯 JS） | 写 | 备注 |
|---|---|---|---|---|
| WKT / EWKT / WKB | ✅ | ✅ `@terraformer/wkt` | ✅ | 模型首选交换格式；必须显式 CRS |
| GeoJSON / NDJSON | ✅ | ✅ 原生 | ✅ | RFC 7946 假设 WGS84，违例要检测并报错 |
| SHP | ✅ 完整 | ⚠️ `shpjs` 覆盖常见 2D，编码与字段类型有限 | ✅ | 文件族；`.prj` 与 `.cpg` 是两个杀手 |
| GDB | ✅ **读 ≥ GDAL 1.11；写 ≥ GDAL 3.6** | ❌ **无兜底** | ⛔ **v1 不做**（技术上可行） | 驱动已内置；SDK 已 Apache-2.0；写只产 v10.x |
| PostGIS | ✅ PG 驱动 | ✅ `pg` 直连（**不依赖 GDAL**） | ✅ 默认只读 | 网络不受沙箱保护；必须参数化 + 超时 |

**这张表直接定义产品的降级行为**：没有 GDAL 时，WKT / GeoJSON / PostGIS 照常工作，SHP 降级，**GDB 明确不可用并给出升级指引**。

### 7.8 对工具契约的影响

- `gis_inspect`：加 `layers: [{ name, geometryType, featureCount, srid, bbox }]`（GDB / PostGIS 多图层）、`crs: { epsg, wkt, source: 'prj' | 'native' | 'assumed-rfc7946' | 'unknown' }`、`encoding: { used, source }`、`capabilities: { read, write, tiles }`；
- `gis_query`：加 `geometry: 'none' | 'wkt' | 'geojson'`（默认 `wkt`，省 token）与 `layer`；
- `gis_convert`：加 `encoding`、`assumeCrs`、`layer`（GDB 选层）、`targetFormat`；
- **`gis_capabilities` 承担连接清单**：列出 / 测试 PostGIS 连接，**只回显 host/db/user/schema 与「密码是否已配置」**（原 `gis_connections` 已并入，见附录 A）。

## 八、零服务预览：不发布地图服务也能浏览大数据

**原则：把「发布地图服务」换成「按需取数」。** 不部署 GeoServer / MapServer / 瓦片服务，不额外监听端口——DSH 自己的本地 web server 就是唯一 HTTP 端点，且所有数据路由都在鉴权栅栏内。大数据靠**格式 + 范围请求 + 缓存**解决，而不是靠先把数据发布出去。

### 8.1 五种零服务取数手段

| 手段 | 解决什么 | 怎么做 |
|---|---|---|
| **COG**（Cloud Optimized GeoTIFF） | 大栅格按需读 | `gdal_translate -of COG -co OVERVIEWS=YES` 生成一次；浏览器用 `geotiff.js` 走 HTTP Range，只取当前视窗与概览层 |
| **概览金字塔** | 缩小时不读原图 | `gdaladdo -r average`；COG 自带 overview |
| **PMTiles** | 矢量/栅格瓦片单文件 | 单文件归档 + Range 请求，MapLibre 用 pmtiles 协议直读，**不需要瓦片服务器** |
| **FlatGeobuf** | 大矢量按 bbox 流式查 | 带空间索引，按 Range 流式读，只取 bbox 命中的部分 |
| **按需 MVT** | 大矢量分层显示 | `ogr2ogr -f MVT` 按 zoom/bbox 生成到缓存目录，路由命中即服务 |

**关键：插件必须提供一个支持 HTTP Range 的路由。** `geotiff.js` 与 `pmtiles` 会自己发 Range 请求，需要 `Accept-Ranges: bytes` + `206 Partial Content` + `Content-Range`。宿主现成的 `/api/file` 只做整文件 GET/HEAD（超限 413），**不满足 Range 语义**，所以这条必须自建：

```
GET /api/gis/blob?id=<datasetId>   # Range-capable；只认注册表里的不透明 id，不接任意路径（路由总表见 3.5）
```

> **对 6.4 的修正**：那里写的「用 `workspaceFiles.readBytes` 分窗读」只能当**兜底**——单窗口 2 MiB，每次一个 RPC 往返，对 COG 这种需要连续 Range 的场景不合适。**主路径是插件自己的 Range 路由**；只有在没有 Range 支持时才退而求其次。

### 8.2 属性表永远分页，不整表

大图层的属性表不下发整表：`gis_query` 走 `ogrinfo -sql "SELECT ... LIMIT ? OFFSET ?"` 或 DuckDB spatial，返回 `{ columns, rows, rowCount, truncated }`，并配 `ORDER BY` 保证分页稳定。

### 8.3 派生数据缓存（含配额）

COG / PMTiles / MVT 金字塔 / 缩略图都是**派生数据**，统一放 `<DSH_HOME>/gis/cache/<dataset-hash>/`：

- 缓存键 = 源文件路径 + mtime + size + 转换参数，源一变自动失效；
- **配额（默认 5 GB）+ LRU 淘汰**，设置页可调、可一键清空；
- 理由：宿主附件库是**永不自动删除**的（见第十二节第 9 条），所以派生数据必须自带配额——不能把一个 20 GB 栅格转出来的瓦片无限堆在磁盘上；
- 派生数据默认落在 `DSH_HOME` 而不是用户工作区，避免污染用户的仓库。

### 8.4 渐进式加载

1. 先出**概览层**（低分辨率）秒开；
2. 空闲时再补细节层；
3. 元数据（CRS/范围/要素数）走 `gis_inspect`，与几何数据分开取；
4. 超过阈值的图层**自动降级为瓦片模式**，而不是先试着全画一遍。

## 九、地图服务：WMS / WMTS / WFS 的浏览与使用

### 9.1 与第八章不矛盾——一个是不发布，一个是去消费

- **第八章**说的是：我们**不需要自己发布**地图服务，本地数据靠按需取数（COG / Range / PMTiles）就能浏览；
- **本章**说的是：我们**要能消费别人的** OGC 服务（WMS / WMTS / WFS）。

我们只实现「**客户端 + 本地适配层**」——能力解析、代理、缓存、瓦片适配，**不实现服务端**。适配层跑在本地 DSH 进程内，所以**依然没有对外发布任何服务**。两者在同一张地图里混用：本地 COG/GeoJSON 图层 + 远端 WMTS 底图 + WFS 要素图层。

### 9.2 三种服务的能力完全不同，不要混为一谈

| 服务 | 返回什么 | 关键操作 | 在 DSH 里的角色 |
|---|---|---|---|
| **WMTS** | 预渲染**瓦片** | GetCapabilities / GetTile / GetFeatureInfo | 与 XYZ 兼容的矩阵集可直接当底图；**但 MapLibre 没有 WMTS 源**，其栅格模板只替换 `{z}/{x}/{y}`，所以**适配层是必需而非优化** |
| **WMS** | 按 bbox 现渲染的**图片** | GetCapabilities / GetMap / GetFeatureInfo | 需要**瓦片适配层**（z/x/y → GetMap + 缓存）才能当地图源 |
| **WFS** | **矢量要素**（GML / GeoJSON） | GetCapabilities / DescribeFeatureType / GetFeature | 取数 → 转 GeoJSON / WKT → 参与查询与转换 |

### 9.3 一律走宿主代理，不让浏览器直连

三个理由，任何一个都足够：

1. **CORS 不一致，而非普遍缺失**（此处此前说过头了）：MapLibre 对跨域栅格会设 `crossOrigin='anonymous'`，没有 ACAO 的服务确实拿不到瓦片——但实测 8 个主流公共服务里 **6 个返回了 `Access-Control-Allow-Origin: *`**（OSM、NASA GIBS、USGS、Esri、swisstopo、PDOK 等），另两个没有。所以**代理的正当理由是下面第 2、3 条（凭证、缓存与错误归一），不是「反正都会被 CORS 挡住」**；
2. **凭证**：很多服务要 `apikey=` 或 Basic Auth，**绝不能落到页面里**；
3. **缓存与限流**：统一在宿主侧做缓存、超时、重试与错误归一。

因此新增两条**注册在 `ctx.connection.fetch` 鉴权栅栏内**的代理路由：

```
GET /api/gis/tile?src=<serviceId>&z=&x=&y=     # WMTS 直取 或 WMS GetMap 适配
GET /api/gis/features?service=&type=&bbox=&count=&startIndex=   # WFS GetFeature

（**不要**写成路径段参数——`connection.fetch` 只匹配 exact pathname，见 3.5）
```

### 9.4 ⚠️ 必须纠正的前提：`ctx.web.fetch` 不能用于地图服务

我先前建议「出网能走宿主 web seam 就走它」——**核实后不成立**（`packages/web/web/src/types.ts:64-97`）：

- `WebFetchRequest` 只有 `{ url }`，**没有 headers、没有 method、没有超时** → 发不了 `Authorization` / `apikey` / `Accept: application/json`；
- `WebFetchBody` 是**封闭联合**，只有 `html` 与 `text` 两支，源码注释明确写着「a new kind is a coordinated change across known packages, **not a plugin extension**」→ **拿不到二进制瓦片**。

结论：OGC 客户端必须走**自己的 HTTP 路径**（宿主进程内的 `fetch`），因此也必须**自己承担**本来由 seam 集中负责的事——连接/读取超时、响应体大小上限、重定向次数上限、出网白名单。这一条要落到安全章。

### 9.5 SSRF：新增服务 = 让宿主去 fetch 任意 URL

这是本功能最现实的安全问题——模型可能被诱导添加一个恶意服务地址。**只在注册时校验主机名是不够的**，真实绕过发生在第二次解析。必须：

- **逐跳校验，而不是只看第一次**：每个请求（含每次重定向）都重新解析主机名；
- **只允许全局单播地址**：拒绝环回、link-local（含 `169.254.169.254`）、私网（`10/8`、`172.16/12`、`192.168/16`）、**IPv6 的 `::1` / `fc00::/7` / `fe80::/10`**、`0.0.0.0`，以及**十进制/八进制/十六进制形式的 IPv4**（`2130706433` = `127.0.0.1`）；
- **用解析结果直连**（解析出的 IP 直接连，不再让 DNS 二次解析），这样 **DNS rebinding** 才挡得住；
- **重定向逐跳复检 + 次数上限**，禁止跳转后降级到 http；
- 响应体大小上限 + 连接/读取超时；
- `gis_service_add` 的返回值里**回显实际请求的最终 URL**，让用户看得见。

- 只允许 `http` / `https` 协议；
- **默认拒绝环回、link-local 与私网段**（`127.0.0.1`、`169.254.169.254` 云元数据、`10.` / `172.16-31.` / `192.168.`），除非用户在设置里**显式放行**——内网 GIS 服务是合理需求，所以是「默认拒绝 + 显式放行」，而不是一律禁止；
- 响应体大小上限 + 超时 + 重定向次数上限；
- `gis_service_add` 的返回值里**回显实际请求的最终 URL**，让用户看得见。

### 9.6 坐标轴顺序：最容易静默出错的地方

- WMS **1.1.1**：`SRS=EPSG:4326`，`BBOX=minx,miny,maxx,maxy`（**经度在前**）；
- WMS **1.3.0**：参数名变成 `CRS`，且 `EPSG:4326` 按 EPSG 轴序是**纬度在前**（`miny,minx,maxy,maxx`）；
- 同类陷阱出现在 WFS 1.1.0 / 2.0 的 `BBOX`、`DescribeFeatureType` 的 `srsName`、GML 几何的 `srsName`。

对策：内部统一 `lon,lat / EPSG:4326`，只在边界转换；**能请求 `CRS:84` 就请求 `CRS:84`**，从根上绕开轴序；把**实际发出的 URL** 记进日志与返回值，方便对账。**但要注意两点**：`CRS:84` 必须在 GetCapabilities 里被通告，并非所有服务都提供；也有服务（如 GeoServer 的 Force XY）干脆忽略轴序。所以**不能盲信 `CRS:84`**，要保留 **per-service 的轴序覆盖开关**。

### 9.7 WFS：解析与分页是风险点

- 输出格式优先 `application/json`（OGC 通告为 `application/json` 或 `application/json; subtype=geojson`）；**WFS 2.0 的默认输出是 GML 3.2**。
- **⚠️ GML 解析必须同时认三代包装**（此处此前只写了 1.1 的形状，是个真 bug）：
  - WFS **2.0**（GML 3.2）→ `wfs:FeatureCollection` → **`wfs:member`**；
  - WFS **1.1**（GML 3.1）→ `gml:featureMember`；
  - WFS **1.0**（GML 2）→ `gml:featureMembers`。
  **只认 `gml:featureMember` 会在标准 WFS 2.0 服务上静默返回 0 个要素**——这恰好违反本节自己定的「绝不静默丢几何」规则。几何侧支持 `gml:posList` / `gml:coordinates` / `gml:Point`+`gml:pos`。
- 分页：WFS 2.0 用 `count` + `startIndex`，读回 `numberMatched` / `numberReturned`；WFS 1.1.0 **只有 `maxFeatures`，没有 `startIndex`**（`STARTINDEX` 是厂商扩展）。三个坑：**`numberMatched` 可能是字面量 `"unknown"`**，不要当数字解析；`startIndex` 自 2.0.2 起是 0 基，但 MapServer ≤ 6.2 从 1 开始计数（GDAL 用 `OGR_WFS_BASE_START_INDEX` 处理）；**服务可能忽略或限制分页**，所以要**自动探测能力 + 检测无进展循环**，不要假定分页一定生效。
- **永远不要假设一次能取完**，如实回 `truncated` 与总数。
- **不支持 WFS-T 事务写**。
- XML 解析用 `fast-xml-parser`（已在依赖树中，5.11.1）；超大 GetCapabilities 用流式 `saxes`，避免把几十 MB XML 一次性变成 DOM。

### 9.8 GetCapabilities 的处理

- 可能非常大（几十 MB）→ **流式解析 + 大小上限**；
- **缓存 + TTL（默认 24h，可配）+ 手动刷新**——能力文档大且很少变；
- 抽取：图层/要素类型清单（`name`、`title`、`abstract`、CRS、bbox、`queryable`）、`TileMatrixSet` 与 `TileMatrixSetLink`、`ResourceURL`（区分 KVP 与 RESTful）、支持的图像格式；
- **必须记录并展示 `Attribution` / `Fees` / `AccessConstraints`**——很多服务对署名与用量有要求。这既是负责任使用，也让用户知道自己在用什么。

### 9.9 WMTS 映射到地图源要处理的细节

- **两种请求编码**：KVP（`?SERVICE=WMTS&REQUEST=GetTile&...`）与 RESTful（`/{TileMatrix}/{TileRow}/{TileCol}.png`）——按能力文档里的 `ResourceURL` 决定；
- **瓦片矩阵不是 slippy 的 z/x/y**：`pixelSpan = scaleDenominator × 0.28e-3 / metersPerUnit`，`tileSpan = tileWidth × pixelSpan`，`TileCol = floor((tileMinX − originX) / tileSpanX)`，`TileRow = floor((originY − tileMaxY) / tileSpanY)`。**翻转规则要更正**：WMTS 1.0.0 把原点**定义为** `TopLeftCorner`（= minX, maxY），TileRow/TileCol 从左上向右下递增，所以**合规矩阵集（如 GoogleMapsCompatible）根本不需要翻转**（`TileMatrix=z, TileCol=x, TileRow=y`）；只有 TMS 2.0 的 `bottomLeft`（`tms`）约定才需要 `TileRow = MatrixHeight − 1 − y`。另注意 `TopLeftCorner` 坐标跟随 **CRS 轴序**；
- 瓦片尺寸可能不是 256（512 很常见）；
- 只请求 `TileMatrixLimits` 允许的范围；越界**在本地返回 404 / 204**——**不要返回透明瓦片**（WMTS 规定越界请求 SHOULD 返回异常响应；而透明块在不透明底图上看起来像数据缺失），当然也不要打服务。

### 9.10 工具契约

> **名称与参数的唯一权威是附录 A**；下表只列服务类工具的设计要点。

| 工具 | 作用 | 要点 |
|---|---|---|
| `gis_service_add` | 添加服务：拉 GetCapabilities 并归一 | 回 `{ serviceId, kind, version, title, layerCount, attribution }` + **实际请求 URL** |
| `gis_service_info` | 服务详情**与图层清单**（合并了原 `_layers`） | 含 `fees` / `accessConstraints` / `attribution`，以及 `{ layers, truncated }` |
| `gis_service_fetch` | WFS 取要素 | **几何默认回 WKT**（与第七章一致）+ 分页 + `truncated` + **三代 GML 包装** |

出图预览**并入 `gis_render`**——图层来源（本地数据集 / PostGIS / OGC 服务）是细节，不是工具边界。

### 9.11 离线与降级

- 服务不可达时给**明确状态**而不是空白图层；**已缓存的瓦片继续渲染**；
- 所有远端调用硬超时；批量取要素走 `ctx.jobs.start` 后台化；
- 服务定义与缓存落 `ctx.storageDomain`，重启后服务列表仍在。

### L1 GDAL/OGR CLI（主推）
事实标准，格式覆盖近乎完备。经 `ctx.sandbox.confine(argv, policy)` + `ctx.subprocess.spawn({ argv, env })` 调用（**先收窄再执行**，见第十二章第 3 条）：

- 探测：配置 `gdalBinDir`，否则查 `PATH`；用 `gdalinfo --version` 判定可用性与版本。
- 常用：`gdalinfo`（元数据）、`ogr2ogr`（转换/重投影/裁剪/过滤）、`gdal_translate`（COG 生成）、`gdalwarp`（栅格重投影）。
- **必须显式传参，禁止拼 shell 字符串**：用结构化 argv，避免路径注入。
>
> **🔴 服务类的字段必须用 TypeScript `private`，绝不能用 `#private`（M1a 实测）**：Cordis 通过 **`Proxy`** 分发服务，而 **ECMAScript 私有字段不会穿过 Proxy**。在代理上调用方法时 `this` 是 Proxy，`#field` 声明在目标对象上，于是抛 `TypeError: Cannot read private member #x from an object whose class did not declare it`，**整行激活失败**。TS 的 `private` 编译期擦除、运行时是普通属性，可穿过 Proxy。**单元测试永远发现不了**——直接调用时没有 Proxy。
- 缺失时的用户体验：`gis_inspect` 仍能工作（走 L0），但在结果里带一条 `issues: [{code:'GDAL_UNAVAILABLE', ...}]` 和安装指引。

### L2 DuckDB spatial（可选）
`@duckdb/node-api` + spatial 扩展，适合大表的 SQL、空间连接、GeoParquet。作为 `gis_query` 的一个 Provider，按"数据规模/格式"路由。

### L3 QGIS（可选）
`qgis_process`（**QGIS 3.14+** 起的无头接口，此前写成 3.24 是错的）能覆盖制图与复杂分析算法。同样是独立进程调用。
**注意**：QGIS 本体是 GPL-2+；以独立进程方式调用不传染本项目，但要在文档里向用户说明他们需要自行安装并遵守其许可。

### L4 远端 / MCP
- 任意符合 MCP 的 GIS 服务（PostGIS、GeoServer 桥、云 GIS）直接用宿主的 `@deepseek-ai/dsh-mcp-client`，无需本项目写代码：**一个 Loader 行 = 一个 server**，配置 `serverName` + `transport`（**只有 `stdio` 与 `streamable-http`，legacy HTTP+SSE 不开放**）+ `command/args/env/cwd` 或 `url/headers`，工具以 `mcp__<serverName>__<tool>` 出现。
- 资源可读：`ctx.mcpResources` 暴露 `list_mcp_resources` / `list_mcp_resource_templates` / `read_mcp_resource`；**MCP prompt templates 不支持**；服务器自带 instructions 会作为 `mcp:<server>` 段进入系统提示词。
- stdio 子进程环境变量会被清洗（丢弃匹配 `KEY|PASSWORD|SECRET|TOKEN` 的变量与 `DSH_*`），凭证走 `ctx.credentials`。
- 本项目可以顺带**提供一份 MCP 预设片段**（文档形式），让用户复制进 profile。

> **许可证与版本**：上表已用 `npm view <pkg> version license` 核对，许可证正文取自各项目源。GDAL 为 **MIT**（gdal.org/license.html）；**QGIS 与 PostGIS 为 GPL-2.0-or-later**（源码头写明「version 2 … or (at your option) any later version」）**——以独立进程 / 独立服务方式调用不构成链接**，可以放心集成；真正的许可决策点是「是否把它们的代码打进分发产物」（结论：不要打）。
>
> PostGIS 客户端可选 `pg` 8.23.0（MIT）或 `postgres` 3.4.9（Unlicense）；DuckDB 侧 `@duckdb/node-api` 1.5.5-r.5（MIT）与 `@duckdb/duckdb-wasm`（浏览器）；`gdal-async` 3.11.5（Apache-2.0）**仅在能同时解决 Node 与 Electron 的 ABI 预编译问题时**才考虑。

### 依赖形态上的取舍

- **不要在 npm 依赖里直接引 `gdal-async` 这类原生绑定**：跨平台预编译包缺失会让 `dsh plugin add` 直接失败，把插件变成"装不上"。GDAL 一律走 CLI；纯 JS 兜底保证无 GDAL 时也可用。
- 浏览器渲染库（MapLibre/deck.gl）内联进 `ui-gis` 的客户端 bundle，并用 `import()` 懒加载，避免拖慢 GUI 启动。

## 十一、设置页：路径与环境变量

需求：**即使用户不在系统环境变量里配任何东西，插件也能直接调用 QGIS / GDAL。**

### 11.1 为什么这条路走得通

`ctx.subprocess.spawn()` 接受 `env` 选项，语义正好够用（`packages/subprocess/subprocess/src/types.ts:99-106`，原文注释）：

- 显式条目**合并到实现自带的、已擦洗的父环境之上**；
- **字符串值是调用方的刻意选择**——所以哪怕名字像凭证、或是 `DSH_*`，也会**保留**、不被擦洗；
- **`undefined` 是墓碑**，会把同名变量**从子进程里删掉**。

这三条恰好覆盖 GIS 的真实痛点：

- 注入 `GDAL_DATA` / `PROJ_LIB`（PROJ ≥ 9.1 为 `PROJ_DATA`）/ `QGIS_PREFIX_PATH` / `PYTHONPATH` / `PATH` → 用户不用配系统变量；
- 用 `undefined` **删掉一个错的环境变量**——这是 GDAL 最经典的故障：系统里有个指向旧 `proj.db` 的 `PROJ_LIB`，导致坐标系全面错乱。**能删比能加更重要。**

### 11.2 一个必须知道的限制

`@deepseek-ai/dsh-shell-env` 提供的托管环境**只接受 `DSH_*` 键**（贡献者必须声明它可能返回的每一个 `DSH_*` 键）。**它无法把 `PROJ_LIB` 注入到模型自己跑的 `bash` / `pwsh` 命令里。**

后果：模型若直接用 shell 跑 `ogr2ogr`，拿不到设置页里配的环境。两个应对：

1. **主路径**：让模型用 `gis_*` 工具——由我们的 Provider 自己 spawn，环境由我们注入，永远正确；
2. **兜底**：提供 `gis_env` 工具，返回当前解析好的环境并生成可直接使用的前缀（bash 的 `export PROJ_LIB=...` / pwsh 的 `$env:PROJ_LIB=...`），或在 `<DSH_HOME>/gis/env.sh`、`env.ps1` 生成可 source 的包装脚本，让模型在不得不用 shell 时自己带上环境。

### 11.3 可执行文件发现顺序（照抄 `pwshPath` 的成熟做法）

`pwsh-local` 的 `pwshPath` 语义是「显式配置 → 已知安装位置 → PATH」。GIS 侧照搬：

| 工具 | 配置字段 | 发现顺序 |
|---|---|---|
| GDAL（`ogr2ogr`/`gdalinfo`/`gdal_translate`/`gdalwarp`/`gdaladdo`） | `gdalBinDir` | 显式目录 → OSGeo4W / conda-forge / QGIS 自带 GDAL 的已知位置 → PATH |
| QGIS（`qgis_process`） | `qgisProcessPath` | 显式路径 → 已知安装位置（含 Windows 的 `qgis_process-qgis.bat`）→ PATH |
| 包装脚本 | `launchPrefix: string[]` | 例如 OSGeo4W 需要先跑 `o4w_env.bat`。**`argv` 从不经 shell 解析**，所以包装必须写成「可执行文件 + 参数数组」，不能写成一行 shell 命令 |

**探测必须真的执行**：跑 `gdalinfo --version`、`qgis_process --version`，并把版本、`GDAL_DATA` / `PROJ_LIB` 的**实际解析结果**、可用驱动数量都报出来——而不是只看文件存不存在。

### 11.4 设置页怎么落地（含一处纠正）

> **纠正**：我原先以为「声明 `.volatile()` 字段就能自动得到表单」——**不对**。`ctx.settings` 的 README 写明 schema 自动生成页面的 `autoGenerate` 目前**没有任何已发布客户端实现**（no shipped client does so yet），`ui-settings-plugins` 里也没有任何 `configForms` 用法。**设置卡片必须自己写**——`ui-settings-shell` 就是手写卡片 + `SettingsForm` / `SettingsFormModel` 的先例。

正确分工是**数据面 + 界面**两层：

**数据面（这部分是免费的）**——`Config` 字段加 `.volatile()`，由 `ctx.settings` 提供：

- 按 profile 条目 id 寻址、带 revision 的读写，**拒绝过期写入**；
- 写入持久化到当前 profile 的 Cordis patch，也就是用户自己的覆盖值，而不是我们包的默认值；
- `role('secret')` 的值会被**脱敏**，客户端只拿到「是否已配置」的标记、拿不到值——**凭证一律走这条，不要自己发明存储**。

```ts
export interface Config {
  gdalBinDir: Volatile<string>                 // '' = 自动探测
  qgisProcessPath: Volatile<string>
  launchPrefix: Volatile<string[]>             // 包装 argv 前缀（如 OSGeo4W 的 o4w_env.bat）
  extraEnv: Volatile<Record<string, string>>   // 注入子进程
  unsetEnv: Volatile<string[]>                 // 从子进程环境中删除（墓碑）
  defaultCrs: Volatile<string>
  cacheDir: Volatile<string>
  cacheQuotaMb: Volatile<number>
  timeoutMs: Volatile<number>
}
```

**界面（要写，但很小）**——注册一张卡片到 **`plugins.bundle.config`**（key = 本包包名，渲染在我们这个 bundle 自己的页面上），用 `ui-primitives` 的 `SettingsForm` + `SettingsFormModel`，通过 `ctx.configForms.get` / `ctx.configForms.whileServed` 绑定。

- **「检测」按钮**：探测 GDAL / QGIS，显示版本、解析出的 `GDAL_DATA` / `PROJ_LIB`、驱动数量；
- 探测失败时给**具体的安装指引**，而不是一句「未找到」；
- 环境变量的**键值对编辑器**（`extraEnv`）+ 需要删除的变量列表（`unsetEnv`）；
- 「恢复默认」「清空缓存」「查看将执行的确切命令行」。

> **注意**：设置卡片是**客户端代码**，所以它和第 0 步 spike 是同一件事——**设置页不是「零 UI 成本」，它是必需的客户端工件**。这进一步说明第 0 步必须先做通。

### 11.5 版本与状态迁移

三处会随版本演进，各自定规矩：

| 载体 | 版本机制 | 规矩 |
|---|---|---|
| 包版本 | `package.json` 的 `version` + `engines.dsh` | 内核是 alpha，锁定 `@deepseek-ai/*`；升级前先跑真实组合测试 |
| 设置 | `.volatile()` 字段持久化在 profile 的 Cordis patch | **只增不改名**；改名要留一个版本的别名兼容 |
| 持久状态 | `ctx.storageDomain` 的 `version` / `compatibleVersions` | 破坏性变更必须升版本；缓存目录按内容哈希命名，可整体丢弃重建 |

原则：**能重建的就不要迁移**。派生缓存（COG / MVT / 瓦片）随时可删；真正需要迁移的只有数据集登记与服务定义。

### 11.6 文案与 i18n

- 插件自带命名空间（如 `gis`）：`ctx.locale.register('gis', { zh, en })`，组件在 `register({ locale: 'gis' })` 后拿到类型化 `t`；
- **展示元数据**：`locale/en.json` + `icon`（`packages/util/package-manifest`），否则插件列表里只有技术名；
- **工具描述、错误码、系统提示词分节一律不翻译**——它们进的是模型上下文，必须稳定可比；
- **只有给人看的**（设置页、卡片标题、按钮）才走 `t`。这条界线别搞反。

## 十二、安全与沙箱

这是 GIS 插件最容易出事的地方——它天生要读任意文件、要起外部进程、还要把字节发给浏览器。

1. **文件读取必须落在授权范围内。** 数据集注册时用 `ctx.fs.resolve()` 把路径规范化并对齐工作区根；路由只接受**注册表里的不透明 id**，永远不接受客户端传来的任意路径。这直接堵死"把 `/api/gis/datasets?path=../../.ssh/id_rsa` 变成任意文件读取"这一类漏洞。

2. **浏览器字节走鉴权栅栏。** 用 `ctx.connection.fetch.register(...)`——它本身就是为「在 Connection 的认证栅栏内注册路由」设计的（`present-open.ts` 注释原文），`/api` 前缀归 Connection 所有并施加浏览器信任栅栏（`admit()` / `--trusted-host`）。**反过来必须记住：`ctx.webServer.register(...)` 裸注册的路由没有任何鉴权**（底层是 `node:http`，无 TLS、无认证、无同源策略，见 `packages/host/webserver/README.md:39`）。用 `webServer` 提供瓦片就得自己把校验写全；能用 `connection.fetch` 或 Typert `@Remote` 就别用 `webServer`。

3. **外部进程分两条缝，别搞混（这条此前写错了）。**

   - `ctx.shell` 吃的是**命令字符串**（POSIX 上经 `bash -c`）；
   - `ctx.subprocess` 吃的是 **argv，且从不经 shell 解析**（源码注释：Never shell-interpreted here）——**但它本身不带沙箱策略**。

   所以规范路径是**先 confine 再 spawn**：

   > **必须显式传 `cwd`（M0 实测）**：省略 `cwd` 会在 `validateNoNullByte('options.cwd', spec.cwd)` 处抛出 `TypeError: Cannot read properties of undefined (reading 'includes')`——因为该函数在墓碑过滤**之前**无条件校验 `cwd`。报错与真正原因无关，极难定位。

   ```ts
   const confined = await ctx.sandbox.confine([bin, ...args], policy)   // 收窄 argv
   const handle = ctx.subprocess.spawn({ argv: confined.argv, env, cwd, stdio, graceMs })
   ```

   （`packages/sandbox/sandbox/src/index.ts:153-176`；真实用法见 `packages/sandbox/sandbox-local/tests/seatbelt.e2e.ts:48`）**绝不用 `child_process` 绕过**；也不要以为「用了 `ctx.subprocess` 就自动安全」——沙箱必须显式 confine。

4. **超时与产物上限。** 工具声明 `ToolDefinition.timeoutMs`（guard 超时会兜出 `TOOL_TIMEOUT`）并转发 `exec.signal`；stdout 用 `SubprocessCollect.maxBytes` 限流，超大产物交给 **`ctx.spillStore.saveText(...)`** 换 `SpillRef { locator, bytes, retrievalHint }`，不要把几十 MB 的 `gdalinfo` 灌进上下文。

5. **返回给模型的量要有上限。** `gis_query` 必须有 `limit` 与 `truncated`；几何坐标要按 bbox 与精度简化（simplify），否则一个省级路网能把上下文烧穿。展示层的 MVT/GeoJSON 也一样要有 `maxFeatures`。

6. **不把凭证写进返回值。** 连 PostGIS/云 GIS 时，连接串与密码走 `packages/credentials` 域名，不进工具输出、不进 `presentationMeta`。

7. **依赖审计。** 内联进浏览器 bundle 的第三方库需要固定版本并做供应链审查；本项目的 `dsh-gis` 一旦被 `dsh plugin add` 就是**在用户机器上执行代码**。

8. **沙箱只管文件效果，不管网络。** 沙箱词汇（`read-only` / `workspace-write` / `danger-full-access`，失败即 `SANDBOX_UNAVAILABLE` 而非静默放行）**只约束文件写入效果**。抓取远端 WMS/XYZ/瓦片**不受它保护**——出网策略必须自己定。

   > **规范要求**：OGC 客户端不得使用 `ctx.web.fetch`（它只有 `{ url }`、且响应体是封闭的 html/text 联合，发不了 API key、拿不到二进制瓦片），必须走自有 HTTP 路径并**自行补齐**超时、响应体上限、重定向上限与出网白名单。完整论证见 **9.4**（此处不重复，避免两份漂移）。

9. **附件库无上限、且永不自动清理。** 通用二进制附件**没有类型白名单、没有大小上限、永不自动删除**（`packages/attachment/attachment/README.md:120`）。用户丢进来一个 20 GB 栅格就会被永久保留。**必须自带保留/清理策略与配额提示**，不能把 `saveFileStream` 当无限仓库用。

10. **设置页本身就是一个执行面。** 允许用户指定任意可执行文件路径与任意环境变量，等价于允许在这台机器上执行任意程序。这是用户对自己机器的显式配置，可以接受，但必须做到：(a) **回显将要执行的完整 argv 与解析后的环境**，让用户看得见自己授权了什么；(b) **`extraEnv` 的值不进日志**（可能含 token）；(c) 执行一律经 `ctx.sandbox.confine` + `ctx.subprocess.spawn`（见第 3 条），不因为「是用户自己配的」就绕过。

11. **PostGIS 是最大的注入面。** 模型输出绝不能拼进 SQL 字符串——**一律参数化**；表名/列名/模式名**无法参数化**，必须先对 `information_schema` / `geometry_columns` **白名单校验**再拼接。连接默认只读（`default_transaction_read_only = on`），写操作显式开启并走审批；强制 `statement_timeout` 与 `idle_in_transaction_session_timeout`，否则一条慢查询能拖死整个连接池。密码只以 `credentialRef` 引用存在，设置页只用 `describe()` 显示「是否已配置」，**永不回显值**。

12. **SSRF 是地图服务功能的首要安全风险。** 「添加一个服务」等于让宿主进程去 fetch 用户（或模型）给出的任意 URL。防护：只允许 `http` / `https`；**逐跳复检**且**只允许全局单播地址**（拒绝环回、link-local 含 `169.254.169.254`、私网、IPv6 的 `::1`/`fc00::/7`/`fe80::/10`、`0.0.0.0`，以及十进制/八进制形式的 IPv4）；**用解析结果直连**以挡 DNS rebinding；重定向逐跳复检 + 次数上限；限制响应体与超时；内网 GIS 服务需在设置里显式放行；`gis_service_add` **回显最终请求 URL**。

## 十三、路线图

> **v1 被刻意砍小**：先交付能用的最小闭环，再按真实人力加面。被推迟的项见本章末尾，削减理由见附录 H。
>
> 人周按「1 名熟悉 TypeScript 但**不熟悉 DSH 内部**的工程师」估，含自测，不含评审等待。

### 第 0 步：可行性验证（≈1 人周）——**唯一出口门：真实客户端构建**

1. 搭最小 bundle 骨架，`dsh --profile gis --dump-config` 能看到本项目的层；
2. 宿主侧注册一个工具，在 GUI 里成功调用；
3. **用真实打包器产出 bundle**：复制 `packages/client/tsdown.client.ts`，替换掉它 import 的 **4 个仓库内文件**（`./modules/src/client/manifest.ts`、`./web/src/platform.ts`、`../../scripts/client-build-environment.ts`、`../../scripts/bundle-input-isolation.ts`），产出一个**两组件、两 chunk（其中一个是 `import()` 懒加载）、带 CSS Modules 注入**的客户端 bundle，并在 GUI 里验证：懒 chunk 按需到达、HMR 免刷新重载。
   - **不要用手写 `client.js`（fixture）当出口依据**：它只能证明「格式可手写」，验证不了 external 与冻结模块表对齐、`require.async` 兄弟 chunk、CSS 注入、combo/rev——而这四个才是真正会翻车的地方；
4. **设置链路**：一张最小卡片写进 `plugins.bundle.config`（key = 包名），改一个 `.volatile()` 字段，确认落进 profile 的 Cordis patch 且重启后仍在；
5. **执行链路**：`ctx.sandbox.confine(argv, policy)` → `ctx.subprocess.spawn({ argv, env })` 跑通 `ogr2ogr --version`，`env` 来自设置；并验证 `undefined` **墓碑**确实删掉一个环境变量。

**出口判定**：

- 第 3 点通过 → 客户端路线成立，按下面阶段推进；
- 第 3 点不通过 → **地图卡片可降级**为服务端出图 + `present`（功能降级，可接受）；
- **但设置卡片不可取消**——它是需求 7 的唯一实现载体。真做不出来必须**显式改需求**，不能在 spike 里顺手放弃。

### 第一阶段 a：懂 + 用（**无客户端代码**，≈2 人周）

与第 0 步的客户端风险**解耦**——这一阶段完全不需要浏览器半。

- `gis-core`：`ctx.gis` 服务 + 数据集登记（`storageDomain`，含 6.6 的 id 派生与 404 语义）；
- `gis-formats` + `gis-purejs`：WKT / EWKT / WKB（默认交换格式）、GeoJSON / NDJSON、**SHP 文件族**（`.prj` 缺失报 `CRS_UNKNOWN`、`.cpg` / 显式 `encoding`）；数据集形态**只覆盖单文件 + 文件族**（GDB / PostGIS 不在此阶段，验收也只验这两种）；
- 工具：`gis_inspect`、`gis_query`、`gis_crs`；
- `prompt-gis`：系统提示词分节 + **2 个**技能（`gis-format-conversion`、`gis-crs-troubleshooting`）；
- `gis_render` **只做服务端 PNG 出图**，产物交给 `present`；
- 派生缓存 + 配额 + LRU。

**退出条件（可执行）**：

- 固定 fixture：一份 GeoJSON、一份**缺 `.prj`** 的 SHP、一份 **GBK 编码**的 SHP；
- 断言：缺 `.prj` → 返回 `CRS_UNKNOWN` 且**拒绝**面积/长度运算；GBK SHP → 属性中文正确；投影坐标的 GeoJSON → 报错而非静默出图；
- 一次真实出图：模型问「这是什么数据、画出来看看」→ 交付 PNG（走 `present`）；
- 单测覆盖 WKT↔GeoJSON 往返与坐标轴序。

### 第一阶段 b：能配 + 能发现（≈2 人周）

- `gis-gdal` / `gis-qgis` Provider：发现链（显式路径 → 已知位置 → PATH）+ **真实探测**（`--version`、`ogrinfo --formats`）；
- **设置卡片**（`plugins.bundle.config`）：`gdalBinDir` / `qgisProcessPath` / `extraEnv` / `unsetEnv` / 缓存配额 / 「检测」按钮；
- `gis_capabilities`（模型第一轮就能问「本机现在能做什么」）与 `gis_env`；
- `ctx.sandbox.confine` + `ctx.subprocess.spawn` 的规范化执行路径 + 环境注入。

**退出条件**：一台**未配任何系统环境变量**的干净机器上，装完插件、在设置页点一次「检测」→ 显示 GDAL / QGIS 版本；配错 `PROJ_LIB` 时用 `unsetEnv` 删掉后坐标系恢复正常（有 fixture 断言）。

### 第二阶段：浏览（**共享地图组件 + 两个宿主面**，≈3 人周）

> 原先「第二阶段做卡片、第三阶段做工作台」的顺序是错的——两者共用地图组件、图层归一化、样式与加载态，分开做等于把同一份地图写两遍。**合并为一阶段：先做组件，再接宿主面。**

- `ui-gis` 第一步：**共享地图组件与图层模型**（`LayerSpec`、样式、空 / 错 / 载态、`--dsw-alias-*` 主题、键盘可达）；
- 宿主面 1：`tool.call.toolview[gis_render]` 会话内联地图卡片 + `presentationMeta` 契约（只放 `/api/gis/blob?id=` 这类路由，见 3.5）；
- 宿主面 2：`ctx.documentPreviews.register` + `sidebar.right.tab.document` 的 GIS 文件预览；
- Range 路由 `GET /api/gis/blob?id=`（206 语义）+ COG 直读（`geotiff.js`）+ PMTiles / FlatGeobuf；
- 首次 COG 转换是**分钟级**操作：必须做成显式后台任务（`ctx.jobs.start`，带进度、可取消、先查配额）。

**退出条件**：

- 2 GB 级 GeoTIFF：**首次**打开走后台转换并显示进度（不谎称秒开）；**再次**打开（缓存命中）≤ 1.5 s 首屏；
- 会话回放后卡片仍可重现；id 失效（源文件被移走）时卡片降级为「数据已不可用」，**不是崩溃**；
- 懒加载 chunk 不出现在首屏网络请求里。

### 第三阶段：PostGIS 与 GDB 只读（≈2 人周）
- PostGIS：`pg` 直连做目录 / 元数据（`geometry_columns`、`ST_EstimatedExtent`）/ 分页查询；凭证走 `ctx.credentials`；`statement_timeout` + 默认只读；**服务端 MVT**（`ST_AsMVT`，不需要 GDAL）；
- GDB：`ogrinfo --formats` 探测 `OpenFileGDB` + 版本门槛（读 ≥ 1.11 / 写 ≥ 3.6）+ 多图层贯通；**v1 只读**（见附录 E）。

**退出条件**：一个 `.gdb` 列出全部要素类；GDAL 版本不足时给出**可执行的**升级诊断（断言文案键，不是断言文案）；PostGIS 慢查询被 `statement_timeout` 掐断且返回 `SQL_TIMEOUT`；`describe()` 只回「已配置」不回值。

### 第四阶段：OGC 地图服务（≈3 人周，**可独立取消**）

> 这是一个**独立产品面**：它的风险（SSRF、CORS、轴序、限流、署名）与其余部分正交，**整体砍掉不影响上面任何需求**。建议单独评审后再决定做不做。

- `gis-ogc`：`GetCapabilities` 流式解析（`saxes`）+ 归一 + TTL 缓存；
- **代理层（独立工作包，不是三句话）**：连接 / 读取超时、重定向上限、响应体上限、并发与限速、重试退避、按服务注入凭证、缓存键含凭证作用域、`Attribution` / `Fees` 展示；
- WMS → 瓦片适配；WMTS 矩阵映射（`ScaleDenominator` / `TopLeftCorner` / **仅 bottom-left 原点需 Y 翻转** / 非 256）；轴序归一（能请求 `CRS:84` 就请求它，并保留 per-service 轴序覆盖）；
- SSRF 防护按 9.5（**逐跳复检 + 只允许全局单播 + 用解析结果直连**）；
- 工具：`gis_service_add` / `gis_service_info` / `gis_service_fetch`。

**退出条件（全部离线可跑）**：fixture + 本地假服务下通过——WMS 1.1.1 与 1.3.0 轴序、WMTS KVP 与 RESTful、Y 翻转矩阵集、不支持的 GML 构造**报错而非丢几何**；黑洞超时 / 重定向环 / 超大响应 / 并发上限各有一条测试；**CI 不出网**。

### 第五阶段：发布与加固（≈1.5 人周）
- 打包产物清单（`files` / `exports`），`pnpm pack` 清单核对；
- **第三方许可与署名**：MapLibre / geotiff.js / pmtiles 等会被**内联进 `lib/client.js`**，必须随附版权与许可声明（生成 `THIRD_PARTY_NOTICES`）；
- CI：Windows 矩阵（路径与编码，风险 9）绿；干净 profile 空环境安装验证；
- i18n（11.6）、`engines.dsh` 具体范围与迁移（11.5）；
- README：三条安装路径差异 + git 安装的 `allowBuilds` 告知。

**退出条件**：干净机器 `dsh plugin --profile gis add <tarball>` 后可用；声明文件生成且被 `files` 收录；Windows CI 绿。

### 明确推迟（不在 v1）

以下项**已从路线图移除**，需要时各自单独提案，不占 v1 预算：

- **deck.gl / CesiumJS / OpenLayers / `@loaders.gl` 与全部 3D**——四套坐标系与图层模型，而需求只要 2D 展示与浏览；
- `conversation.view[gis]` 会话地图视图、`shell.overlay` 全屏地图、输入框 dock 入口——验收表里没有一行对应它们；

- `sidebar.right.pane.tab[gis-layers]` 图层面板、`sidebar.panellist[gis]` + `main[gis]` 工作台——**首版客户端面只留 2 个**（聊天卡片 + 文档预览）；
- 文档预览的卫星插槽 `.unpreviewable` / `.actions`（依赖尚未存在的预览器）；
- 设置页装饰项：`launchPrefix` 图形编辑器、缓存预热、导出 / 导入设置；
- MCP 预设文档（并入后续提案）。

## 十五、测试与验收

**单元测试（vitest）**
- CRS/坐标换算：已知点位的往返精度；跨半球、跨 180° 经线；无 CRS 数据的显式报错。
- 格式识别：扩展名与 magic bytes 冲突时的判定优先级。
- 工具契约：`parameters` 校验、`output.schema` 校验、`presentationMeta` **纯函数性**（同输入同输出、无 I/O）、`truncated` 语义。
- 路由安全：路径穿越、id 伪造、未注册 id → 404，且**不泄漏真实路径**。

**集成测试**
- 用 `packages/test-support` 的插件测试工具起一个最小 Cordis 树，验证 `ctx.gis` 在 Provider 缺失/部分缺失时的降级行为。
- 走一遍"注册工具 → 执行 → `tools/result` 观察"的完整链路。
- **真实组合测试（必须）**：`packages/test-support` 提供 `runLoaderSmoke({ binScript, configPath, tsconfigPath })`，在隔离的 `DSH_HOME` 下真实启动 bin + `cordis.yml`；另有 `agent-loop-testkit`（带 mock LLM 的完整 agent loop）、`llm-replay` / `llm-mock-server`（免密钥）、`remote-mock`、`client-test-runtime`（浏览器半）。`docs/testing.md:39` 明确要求产品可见的插件必须有非单测的真实组合测试——GIS 工具集正是此类。
- **HMR 安全测试**：dispose 掉贡献 fiber，断言注册全部清理（每个注册表都要写，`docs/testing.md:9`）。
- **导出形状回归**：断言 `'default' in mod === false` 这类约定，避免插件形态被无意改掉。
- 断言真实世界，而不是 agent 的自我报告（`docs/testing.md:35`）。

**端到端**
- 参照 `apps/web/tests/*.e2e.ts` 的方式，验证：地图卡片渲染、会话回放后卡片仍可复现、`isError` 降级、`call === null` 降级。

**远端服务（WMS / WMTS / WFS）在 CI 中怎么测**

- **默认不联网**：CI 不访问公网服务，避免 flaky 与合规问题；
- **录制回放**：把 GetCapabilities / GetTile / GetFeature 的响应录成 fixture——至少覆盖 WMS **1.1.1 与 1.3.0 两版**、WMTS 的 **KVP 与 RESTful 两种编码**、以及一个**轴序敏感**的 WFS；
- **本地假服务**：起一个最小 HTTP 端点扮演 OGC 服务，专测**代理、缓存、超时、SSRF 拒绝**这些宿主侧行为（fixture 测不到）；
- **轴序回归**：用一组已知坐标断言发给假服务的 BBOX 顺序正确——这是最容易静默出错的地方，必须有测试钉住；
- **可选联网测试**：单独标记 `network` 档，默认跳过、手动触发。

## 十六、发布与安装

**推荐路径：预构建产物 + npm（或 tarball）**

> **⚠️ 必须锁 `alpha` 通道（M0 实测）**：`@deepseek-ai/dsh-*` 的 `latest` 是**陈旧的 `0.0.1-rc.1`**，且经镜像安装会因依赖一个**从未发布**的 `@deepseek-ai/dsh-type-meta` 而直接失败（npmjs 与 npmmirror 都 404）。可用通道是 **`alpha`（实测 `0.1.7-alpha.2`）**，与内核开发checkout同代。所以依赖必须写死版本，**不要用 `*` 或 `latest`**。

> **⚠️ `allowBuilds` 不只是 git 安装才需要（M0 实测）**：`pnpm install` 在纯 npm 依赖下同样会因为依赖的 postinstall 而被 `ERR_PNPM_IGNORED_BUILDS` 拦下（本次是 `esbuild`）。profile 的 `pnpm-workspace.yaml` 需要：`allowBuilds: { esbuild: true }`。README 里必须写，否则用户第一步就卡住。

```sh
dsh plugin --profile gis add @znlgis/dsh-gis
dsh --profile gis --dump-config     # 确认本项目的层已生效
dsh --profile gis
```

`$DSH_HOME` 解析顺序：显式路径 > `$DSH_HOME` > `~/.dsh`。profile 由 `dsh plugin` 初始化，pnpm 设置为 `nodeLinker: hoisted`、`autoInstallPeers: false`，外加用户可编辑的 `allowBuilds`。内建 profile 模板包括 `web`（`@deepseek-ai/dsh-base` + `@deepseek-ai/dsh-web-app`）、`acp`、`headless`、`sdk`、`sdk-minimal`；不写 profile 时默认 bundle 是 `@deepseek-ai/dsh-base`。图形化安装入口是 Settings → Plugins（背后是 Plugin Manager 的 `@Remote` 方法 `installBundle` / `setPluginEnabled` / `removeBundle` 等），所以本插件装好后会自然出现在插件列表里，**记得提供 `locale/en.json` 与 `icon` 展示元数据**，否则列表里只有技术名。

**git 安装的坑（必须写进 README）**：`dsh plugin add github:znlgis/dsh-gis` 拉的是**源码不是产物**，不会跑构建，TypeScript 包会缺 `lib/` 而加载失败。两条出路：

- 作者侧提供 `prepare` 脚本（自包含、不依赖开发态上下文）；
- 用户侧需要 pnpm ≥10 的 `allowBuilds` 放行——这等于**授权在安装时执行代码**，应引导用户 pin 到具体 commit：`github:znlgis/dsh-gis#<sha>`。

对 GIS 插件尤其推荐 tarball / npm：用户群体里「愿意在安装脚本里放行任意代码」的比例不高，而预构建产物两种安装方式都不需要任何构建许可。

## 附录 C：数据模型草案（TypeScript）

```ts
/** 数据集四态。id 不透明；真实路径永不出现在客户端。 */
type Dataset = FileDataset | FamilyDataset | ContainerDataset | ConnectionDataset

interface DatasetBase { id: string; title: string; layers: LayerRef[] }
interface FileDataset       extends DatasetBase { kind: 'geojson' | 'wkt' | 'ndjson' | 'gpkg' | 'kml' | 'gpx'; path: string }
interface FamilyDataset     extends DatasetBase { kind: 'shapefile'; main: string; siblings: string[] }  // .shp/.shx/.dbf/.prj/.cpg
interface ContainerDataset  extends DatasetBase { kind: 'gdb'; dir: string }                            // 只读
interface ConnectionDataset extends DatasetBase { kind: 'postgis'; profile: PostgisProfile }              // 不含密码

interface LayerRef { name: string; geometryType?: string; featureCount?: number; bbox?: Bbox; srid?: number }
type Bbox = [number, number, number, number]   // [w, s, e, n]，统一 EPSG:4326

interface CrsInfo {
  epsg?: number
  wkt?: string
  source: 'prj' | 'native' | 'assumed-rfc7946' | 'user' | 'unknown'   // 必须如实标注来源
}
interface Capabilities { read: boolean; write: boolean; tiles: boolean; reason?: string }

/** 地图图层描述：进入 presentationMeta 的可回放部分，只放路由不放字节。 */
type LayerSpec =
  | { id: string; kind: 'vector'; url: string; style?: StyleSpec }
  | { id: string; kind: 'raster'; url: string; opacity?: number }
  | { id: string; kind: 'mvt'; url: string; style?: StyleSpec }
  | { id: string; kind: 'bg'; url: string }        // WMTS / WMS 代理瓦片

/** OGC 服务：只存归一后的能力摘要，原始 XML 不入库。 */
interface OgcService {
  id: string; url: string; kind: 'wms' | 'wmts' | 'wfs'
  version: string; title?: string
  attribution?: string; fees?: string; accessConstraints?: string
  layers: OgcLayerRef[]
  tileMatrixSets?: TileMatrixSetRef[]    // WMTS
  fetchedAt: number
}
```

`storageDomain` 的 `version` 随这些类型走；破坏性变更必须升版本并声明 `compatibleVersions`（见 11.5）。

## 附录 D：错误码

工具失败一律 `throw`（registry 归一成 `isError`），但**领域失败必须带稳定 `code`**，让模型与用户能区分「数据问题」和「环境问题」：

| 码 | 含义 | 模型该怎么办 |
|---|---|---|
| `GDAL_UNAVAILABLE` | 没找到 GDAL/OGR | 改走纯 JS 路径，或提示去设置页配 |
| `GDB_DRIVER_MISSING` | GDAL 版本不含 OpenFileGDB | 说明**读需 ≥ 1.11、写需 ≥ 3.6**；**不要重试** |
| `QGIS_UNAVAILABLE` | 没找到 `qgis_process` | 改用 GDAL 等价操作 |
| `CRS_UNKNOWN` | 数据没有 CRS（如缺 `.prj`） | 问用户，或用 `gis_convert --assume-crs` |
| `CRS_MISMATCH` | 参与运算的图层 CRS 不一致 | 先显式重投影，不要隐式转换 |
| `ENCODING_UNDECIDED` | DBF 无 `.cpg` 且未指定编码 | 请用户指定 `encoding` |
| `GEOMETRY_INVALID` | 几何无效（自交等） | 报告并发数，必要时先修复 |
| `LAYER_AMBIGUOUS` | 容器数据集未指定 `layer` | 先 `gis_inspect` 列层再重试 |
| `SERVICE_UNREACHABLE` | 远端服务不可达/超时 | **不要连续重试**；告知用户 |
| `SERVICE_BLOCKED` | SSRF 策略拒绝（私网未放行） | 告知需在设置页显式放行 |
| `SERVICE_AUTH` | 401 / 403 | 提示配置凭证，不要重试 |
| `SERVICE_TOO_LARGE` | 响应超过 `maxServiceBytes` | 缩小 bbox 或改用分页 |
| `WFS_UNSUPPORTED_GML` | GML 构造超出支持范围 | **如实报告**，绝不静默丢几何 |
| `WMTS_MATRIX_UNMAPPED` | 当前 zoom 无对应 TileMatrix | 就近取级或告知超出范围 |
| `SQL_TIMEOUT` | 触发 `statement_timeout` | 缩小范围/加 bbox，不要原样重试 |
| `CACHE_QUOTA_EXCEEDED` | 派生缓存配额满 | 提示可清空缓存 |

## 附录 E：非目标（明确不做）

写清「不做什么」和「做什么」同样重要，可避免范围蔓延：

1. **不发布地图服务**——不实现 WMS/WMTS/WFS 服务端，不额外监听端口；只做客户端与本地适配层。
2. **不做 WFS-T 写事务**；所有 OGC 服务一律只读。
3. **不写 GDB**——技术上 GDAL ≥ 3.6 已可写，但写 GDB 属于**数据编辑**，不在 v1；要输出请转 GPKG / SHP / GeoJSON。
4. **不做 PostGIS 写操作**（v1）：连接默认 `default_transaction_read_only = on`。
5. **不做 3D**（v1）：CesiumJS / 3D Tiles 留到生态阶段。
6. **不做栅格分析**（v1）：重投影与出图可以，坡度/水文/影像分类不做。
7. **不做打印级制图**（图例、比例尺、图廓）——复杂制图交给 QGIS 桌面版。
8. **不做数据编辑 UI**：要素增删改一律不在 v1。
9. **不做多用户/协同**：跟随 DSH 的单机会话模型。
10. **不内置任何商业服务密钥**，也不预置需要注册的底图。

| 轮次 | 方式 | 典型发现 | 性质 |
