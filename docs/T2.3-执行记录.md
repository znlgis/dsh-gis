## 三、四个设计决定

1. **路由住在 `ui-gis` 的宿主半。** 这一半本来就是「浏览器面」的家（DSH 的 `ui-deliverables` 同样在自己的宿主半里注册路由）。它 `inject: ['connection', 'gis']`：没有浏览器面的 profile 里它自然等待，这正是想要的。
2. **安全边界在解析器，不在处理器。** 路由只认一个不透明 id，解析走 `ctx.gis.resolveFresh`（T1a.2）——于是两件事同时成立：**客户端永远无法把 id 变成路径**（设计第十二章），**源变了的 id 在字节被送出之前就被淘汰**。单测里专门的用例把 `?id=../../etc/passwd` 送进解析器，断言它**原样**到达解析器并被 404。
3. **单段 Range 必须流式。** 2 GB 的栅格不能为了 64 KiB 被读进内存：单段用 `createReadStream(path, {start, end})` 直接接成 web stream。多段是例外（要算 `Content-Length`），所以给它加了**字节上限**（默认 8 MiB）：超过就**忽略 Range 头、整份返回**（RFC 9110 明确允许），而不是发一个客户端收不起的响应。
4. **不合法就按 RFC 忽略，而不是猜。** 语法非法的 Range（`bytes=abc`、`bytes=5-2`、非 bytes 单位、成员数超上限）一律**忽略该头、回 200 整份**；语法合法但不可满足（全部起点越界）才回 **416 + `Content-Range` 星号形式**。混合时丢掉不可满足的成员、服务其余的。

另外两个小决定：**ETag 就是数据集 id**（它由内容派生，本来就是实体标签），于是 `If-None-Match` → **304**；`Cache-Control: private, immutable` + `X-Content-Type-Options: nosniff`（Range 响应是形状可控的输入，必须禁止嗅探）。

## 四、实测（两项，全过）

**(1) 字节级单测 19 条**（真临时文件 + 假解析器，`pnpm test`）：

200 的头部齐全（含 `accept-ranges`/`nosniff`/`etag`）· HEAD 同头无体 · **304**（匹配/不匹配）· 单段 206 且切片精确 · 开区间与后缀区间（`bytes=-4` → `bytes 6-9/10`）· 越界钳制 · **多段 → multipart/byteranges**（边界、各段自己的 Content-Range、顺序、`Content-Length` 与实际字节数一致）· **416** · 混合时服务可满足者 · 四类非法/超限 Range → 200 整份 · 多段超预算 → 200 整份 · 缺 id → 400 · 未知 id → **404 + `DATASET_NOT_FOUND`** · **路径形状的 id 不构成路径** · 目录（`.gdb`）→ 404 · 文件在解析后消失 → 404 · 注册的是 `/api/gis/blob` GET/HEAD 且**卸载时归还**。

## 五、过程中的两个小插曲

1. **探针又踩了同一个竞态。** 探针在 `apply` 里立刻 `ctx.gis.open()`，而 `ctx.gis` 在 gis-core 激活时就有了、那时 gis-purejs 还没注册 opener ⇒ `no opener handles ...`。这与 T1a.2 的探针是同一个坑（契约 #19 的脚注），修法也相同：等 opener 认领路径（重试到 60s）。**三次探针、三次同一个坑**——凡是「服务先到、提供者后到」的可选依赖，探针都必须自己等。
2. **`*/` 写在 JSDoc 里会提前结束注释。** 我在头部注释里写了 `Content-Range: bytes */size`，`*/` 把块注释关掉了，后面整段变成代码，TS 报的是「module declaration names may only use quoted strings」和「unterminated template literal」这种**看不出根因**的错。已改写措辞（不再出现字面 `*/`）。

## 六、诚实边界

1. **只实现了路由总表里的第一条。** `/api/gis/geojson`、`/tile`、`/features`、`/catalog` 分别属于 T2.4/T2.5/T3.4/T4，本次没碰。
2. **路由服务的是数据集的「源文件」字节。** T2.4 的 COG 派生件要另有一个来源（缓存目录）——**解析器就是那个缝**（`resolve` 返回 `BlobTarget`，换来源不用动处理器）。
3. **shapefile 只服务主文件（`.shp`）。** 文件族没有逐成员路由；要让浏览器用上 shapefile，得走矢量取数路由（T2.4/T2.5），不是这条。
4. **`.gdb` 与连接类数据集没有字节路由**（不是单个文件）：实测 404。这是有意的，不是缺口。
5. **`EACCES`/`EPERM` → 403 这条分支没有测试覆盖**：在 Windows 上造一个「存在但不可读」的文件不可移植。代码在 `refusal()`/`stat` 的 catch 里，分支很短，但**它未经断言**。
6. **没有 `If-Range`。** 需要原子重验证的客户端请用 ETag（304 已支持）；断点续传的一致性由「内容派生的 URL + immutable」保证。
7. **没有并发/背压测试。** 单段是流式的（有背压），多段是内存内的（有字节上限）；但「多个大 Range 并发时进程内存如何」没有实测。
