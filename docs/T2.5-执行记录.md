## 一、为什么先做这一半

T2.4 留下了明确缺口：**卡片画不出 COG**（geotiff.js 直读未做，浏览器端读不了栅格）。T2.5 的 PMTiles / FlatGeobuf 与它共用同一件事——**按 Range 取数并在浏览器里解码**——所以两者合成一轮，本轮先交付可验证的那半：**COG 直读**，PMTiles/FGB 复用同一条链路（见第七节）。

## 三、实测（三条独立证据）

1. **纯函数 9 条**：1/2/3/4 波段、16 位按声明深度缩放（不是截断）、32 位不缩放（DEM 会变黑）、**只把声明的 nodata 变透明**（数据里的真 0 保留）、>4 波段与空图拒绝、窗口上限保比、角点顺序。
2. **真 COG 4 条**（GDAL 造、GDAL 转）：读出 64×32 与烧录值 200、**范围来自文件自己的 tie point**（100/30/110/40）、300×100 在 `maxSize: 64` 下读成 64×21（**走概视图，不是整幅解码**）、三波段按文件顺序、**投影栅格拒绝**（`CRS_UNKNOWN`）。
3. **真浏览器 7 条**（`pnpm check:cog`）：卡片 ready、地图 ready、画布 675×158、**零 issue**、**字节路由收到多次带 `Range` 的请求且不是整文件**、无页面错误。

## 四、🔴 本轮最重要的一条：跨 chunk 的同步 require 必然失败

内核升到 `0.1.7-rc.1` 后，**地图整条路径都不渲染了**。产品自己给出的错误是：

```
client-modules: require("./client.rolldown-runtime.js") missed the module table —
not a platform seed word, not a materialized module, and no registered package factory
```

读 loader 的 `require` 实现（`client/modules/src/client/system.ts`）：它只认「平台种子」「已 materialize 的模块」「已登记的 factory」。**chunk 之间同步 require 的另一个 chunk，只有在它恰好先被加载时才成立**——顺序没有任何保证。rolldown 只要发现两个动态 chunk 共享一个模块（运行时辅助、`basedecoder`、`pako`…）就会这么发，于是「共享」变成了「断链」。

以前它能跑，是因为**外壳恰好提供了那个 chunk**；内核一升级就没有了。这类缺陷**单元测试与产物契约都只在事后才发现**——它是通过真实浏览器检查抓住的。

**修法**（`scripts/flatten-client-chunks.mjs`，构建步骤）：把被同步 require 的 chunk **内联**进每个引用者（按依赖序，递归），然后删除不再被任何文件需要的 chunk。仍然走 `require.async` 的 chunk 保留为文件。结果：**没有任何 chunk 同步 require 另一个 chunk**——这正是 loader 真正要求的性质，已写成产物契约断言。

## 五、另外两条同源的构建坑

1. **`exports` 条件按包里的顺序匹配，不按我们请求的顺序。** geotiff 的 `exports` 把 `import` 写在 `browser` 前面 ⇒ 客户端包里进的是 **Node 版 ESM**，它经 `web-worker` 摸到 `http` ⇒ 运行期 `require("http") missed the module table`。修法：预设里显式把 `geotiff` 指向它自带的 **UMD browser 构建**（实测：551 kB、零 `http`、零 worker 引用）。
2. **UMD 的动态导入不算「动态 chunk」。** 指向 UMD 后 `import('geotiff')` 被编译成内部 helper 调用，预设的 ESM 检查直接报错（与 M2 早期 MapLibre 那次同一个坑）。修法同样是加一个 **ESM 包装模块**（`map/geotiff.ts`）。

## 六、诚实边界

1. **解码在主线程**（设计 6.4 的 L1 写的是 Web Worker）。窗口上限（长边 2048）让实际解码量很小，但**首帧仍可能卡顿**；Worker 化未做。
2. **只支持地理 CRS**：投影栅格明确拒绝（`CRS_UNKNOWN` + 提示），重投影是 T4 的事。这是有意的「宁可不画也不画错」。
3. **PMTiles / FlatGeobuf 未做**（T2.5 的另一半）：同一条 Range 链路已经跑通，但两者的读取器与图层种类尚未实现，`mapLayersOf` 对它们仍给 `UNSUPPORTED_FORMAT` 说明。
4. **栅格的重采样/拉伸未做**：按声明的位深线性映射，**不自动拉伸对比度**，所以一个值域很窄的 DEM 会看起来接近纯色。
5. **服务端不再为栅格出 PNG**（`image: null`）：这是有意的（卡片就是那张图），但如果有人只需要一张静态图（没有浏览器），现在拿不到——`gis_render` 的散文里写明了。
6. **F8（1.89 GiB）没有在浏览器里跑过**：`check:cog` 用的是 256×128 的小 COG（够验证 Range 与解码链路）；大文件的实际首帧时间未测。
