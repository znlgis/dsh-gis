## 四、怎么做到的（三个关键点）

1. **模型用 mock，不用凭据**：`startMockLlmServer({ sequence: ['tool_call_success','success','tool_call_success','success'], toolName: 'gis_render', toolArguments: '{...}' })`，并经 `DEEPSEEK_BASE_URL` 指过去。
2. **输入框是 Lexical 富文本**，但有稳定钩子：`[data-composer-input="true"]`；发送按钮 `aria-label="发送消息"`。
3. **工具有行锚点**：`[data-tool="gis_render"]`，可点开展开（折叠行没有尺寸，0×0 的容器不算「渲染出来了」）。

## 五、本轮抓到的四件事（全部是真问题）

1. **🔴 可用性探测被浏览器缓存骗了。** 字节路由带 `Cache-Control: private, immutable`（URL 是内容派生的，缓存它是对的），于是探测的普通 `fetch` **由浏览器缓存回答**，把已经失效的 id 报成「还在」。修法：探测显式 `cache: 'no-store'`——它问的是**源站**，不是缓存。
   > 值得记住的张力：缓存里的旧字节对那个 id 而言**本来就是对的**；我们之所以要降级，是因为「id 背后的源已经没了」。
2. **🔴 两个文案键漏注册**，于是卡片把 `render.missing` 这个 **key 原样显示**给用户。浏览器跑一次就露出来了（DOM 车道的断言只看「有 note」所以没抓到）。
3. **图层 id 不能放进译文里**：字典承载不了运行时值，中文译文一出，`(ds_…)` 就没了。改为「译文 + 括号里的 id」，与语言无关。
4. **harness 的两个坑**（都已写进脚本注释）：
   - 会话标题生成器（`session-title-llm`）会**先**向模型要一次名字，把 mock 的 FIFO 第一个行为吃掉——那一轮就成了「1 步、没有工具调用」。修法：验证 patch 里禁用它。
   - mock 的工具调用 id 恒为 `mock-call-1`；**同一会话里第二次调用**会让客户端会话模型拒绝事件流（`received more than one start Match`），整段转录变空。修法：第二轮开新会话（这是 mock 的限制，不是插件的）。

## 六、与计划的一处偏差（有意）

判据写的是「纳入 `pnpm test:web`」，本轮**没有**把它塞进那条车道，而是单独做成 `pnpm check:e2e`。理由：`test:web` 是 1.6 秒的 DOM 车道（145+7 条单测级断言，任何机器都能跑），而这条 e2e 需要 Chromium、需要一个隔离实例、耗时约 3 分钟。两者放一起只会让快车道变慢并变得脆弱。**建议 T5.3 的 CI 把它作为独立阶段**（与 `check:real` / `check:route` / `check:browser` 并列）。

## 七、诚实边界

1. **`call === null`（回放窗口裁掉调用）在浏览器里造不出来**：它要求日志被截断。DOM 车道已覆盖该状态（断言渲染出 `callId`），浏览器层未覆盖。
2. **选择器依赖中文 UI**：发送按钮用 `aria-label="发送消息"` 定位——界面语言一变就失效。输入框的 `[data-composer-input]` 是稳定的，按钮不是。
3. **本机专属路径**：脚本默认 `DSH_REPO=D:/self/code/deepseek-harness`（可用环境变量覆盖）与 `ms-playwright/chromium-*`。CI 上要装 Chromium（T2.10 的后半段/T5.3）。
4. **未做栅格/矢量瓦片的浏览器验证**：卡片今天只画 GeoJSON（T2.4/T2.5 的 COG/MVT 还没有）。
5. **`isError` 的浏览器断言依赖 mock 的第二次工具调用**（新会话里做）；它证明的是「工具抛错 → 卡片出诊断」，**没有**断言错误码的文案正确性（DOM 车道断言了 `[CODE] message` 形式）。
