## 三、四个设计决定

1. **缺陷是数据，不是异常。** 输入是工具结果——可能被回放、截断、或由旧版本插件写入。所以每个缺陷都变成一条 `MapIssue`（`SPEC_INVALID` / `LAYER_*_MISSING` / `LAYER_KIND_UNKNOWN` / `LAYER_DUPLICATE_ID` / `LAYER_SOURCE_LAYER_MISSING` / `LAYER_STYLE_INVALID`），**并且点名是哪一层**，其余照画。空白地图不配解释，本身就是 bug。
2. **三种来源，一种形状。** 渲染路径里**没有任何一个分支能分辨数据来自本地文件、PostGIS 连接还是 OGC 服务**——缝就是 URL。`origin` 只是个标签，测试断言它**不会进入任何 MapLibre 描述**。
3. **宿主声明的样式优先，逐字保留。** 主题 token 只用来填**默认值**（`--dsw-alias-brand-primary` 作要素色等）。理由：回放必须和当初那次运行画出同一张图，二次猜测会破坏这一点。
4. **空视图不加载库。** 没有图层就没什么可画：组件直接给出 empty 态，浏览器不必为了一句话下载 1.5 MB。

## 四、实测（三项，全过）

**(1) 模型 17 条 + 生命周期 10 条**（`pnpm test`，无浏览器）：非对象/缺字段/未知 kind/重复 id/畸形 bbox（长度、NaN、反向）/畸形 style（非对象、未知图元）逐条给出码与层名；**冻结的输入能安全归一**（输出不是别名，改输出不影响输入）；样式解析（宿主 paint 逐字保留、line/fill/circle 默认、mvt 默认 fill、raster 不产生默认 paint 但保留 `raster-opacity`）；token 读取与回退；三种 kind 的 source/layer 描述；**缺 `sourceLayer` 的矢量瓦片被拒绝并点名**；**三种 origin 描述完全相同**。

**(2) 产物契约 22 条**（`pnpm check:bundle`）：在 T2.1 的 21 条之上，新增「**每个 chunk 都能从入口到达**」（孤儿 chunk 检测）。

**(3) 真实浏览器 7 条**（`pnpm check:browser`）：首屏五项 + **MapLibre 能力探针**两项：

```
  PASS  the verification instance announced its URL
  PASS  the page fetched the client bundle
  PASS  the plugin factory ran (its style tags are in the document)
  PASS  the first screen fetched no map chunk and no MapLibre chunk
  PASS  the page raised no error
  PASS  MapLibre initializes in this page (WebGL + inlined blob worker)
  PASS  the map created a sized canvas
BROWSER CHECK PASSED
```

最后两项是这一轮新加的：把**我们发布的那份 5.x UMD** 注入真实页面并真的建一张图，验证「这个浏览器能跑 WebGL」与「CSP 放行 blob worker」——这两件事若为否，T2.6 会以「地图空白」的形式踩到，而那时排查成本高得多。

## 五、🔴 本轮抓到两个真缺陷（都由检查抓到，不是我发现的）

**1. 跨 eager/lazy 的共享模块 ⇒ 插件整半消失。**
T2.2 让 eager 的探针卡片 `import` 了 lazy 图里的 `layer-model.ts`（一个纯函数）。rolldown 立刻把它提升为**共享 chunk**，入口出现**同步 `require("./client.layer-model.js")`**，加载器解不了 ⇒ 工厂抛错 ⇒ **该插件的样式标签整批消失**。

现象是「插件没加载」，根因是一个 import。两条独立检查各自发现一半：

- `check:bundle` 看到结构：入口有同步 chunk require；
- `check:browser` 看到症状：样式标签不见了（并在 20 秒轮询里始终不出现）。

修法：**map 目录下的任何模块都不得被 eager 图运行时引用**（类型导入除外，会被擦除），这条已写进卡片源码的注释，并作为契约 #24 记入 `docs/运行时契约.md`。

**2. 客户端构建不清 `lib/` ⇒ 孤儿 chunk 会被发布。**
预设的 `clean: false` 是有意的（默认清理会连带删掉同目录的 node 半与 `types/`），代价是**离开依赖图的旧 chunk 会永远留在 `lib/`**——本轮就留下了一个没人引用的 `client.layer-model.js`，而 `files: ["lib/client.*.js"]` 会把它一起发布。修法：构建前 `scripts/clean-client-chunks.mjs`，产物里再断言「没有孤儿 chunk」（契约 #25）。

**顺带修掉一个 T1a.10 遗留的抖动测试**：LRU 重启用例依赖「两次写入落在不同毫秒」且**把两个条目都读了一遍**（于是两个都变成"最近使用"，淘汰谁全看运气）。全量跑 5 次能复现 1 次失败。修法：只读必须活下来的那一个；跨重启的顺序改用显式 `utimes` 设定，不再靠时钟。修完连跑 **5 次全绿**。

## 六、诚实边界

1. **地图仍没有产品面。** 组件挂在 M0 探针卡片的开发按钮上；真正的面是 T2.6 的 `gis_render` 卡片，取数要等 T2.3 的 `/api/gis/blob?id=`。所以「**三种来源真的各画出了一张图**」本次仍未验证：验证的是归一、样式、描述与三条来源的同一路径（单测层面），加上浏览器层的库可跑性。
2. **几何感知的默认样式没做。** 默认图元仍是「宿主说，或 circle/fill」。按几何自动选点/线/面需要先看数据（多一次取数），属于 T2.6 与图层联动的范畴。
3. **`basemap` 目前只有 `none`。** 设计 6.3 就是这么定的；底图开关（若要做）属于后续。
4. **没有图层可见性/透明度面板。** 那是设计 6.4 的 L2（右栏图层面板），不在 T2.2 的判据里。
5. **`--dsw-alias-*` 只用于图层默认色**（要素色/描边色/底/边线）；组件自身的外框、徽标等用的是 CSS 变量（T2.1 已在 `map.module.css` 里做）。二者同一个 token 源，但**没有任何断言保证宿主真的定义了这些 token**——缺失时回退到 `DEFAULT_THEME`。
