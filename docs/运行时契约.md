# 运行时契约（实测汇总）

> 本文汇总 M0 / M1a / M1b 三轮实测中发现的**契约陷阱**，是《方案设计》3.7 与附录 I 的配套收口。
>
> **一条共同的形态**：下面每一条的**类型都是对的、编译期都不报错、单元测试也都发现不了**。
> 它们只在「装进 profile、起真实实例、驱动真实界面或真实外部工具」时暴露，
> 而且**几乎全部是静默失败**——没有异常、没有日志，只是行为不对。

## 一、宿主与服务（node 半）

| # | 契约 | 类型怎么说 | 运行时实际怎样 |
|---|---|---|---|
| 1 | 插件注入声明 | 函数形式与类形式都能写 | **函数形式用 `export const inject`；类形式必须用 `static readonly inject`**。类形式下模块级导出被**静默忽略**，直到你访问注入的服务才抛 `cannot get property "x" without inject` |
| 2 | 服务类字段 | `#private` 与 `private` 都是私有 | **Cordis 用 `Proxy` 分发服务，`#private` 不穿过 Proxy**：`Cannot read private member #x from an object whose class did not declare it`，整行激活失败。必须用 TS 的 `private` |
| 3 | `ctx.subprocess.spawn` | `stdio` 看着像字符串 | `stdio` 是**对象** `{ stdin, stdout, stderr }`，且**该接缝不施加任何默认值**——`stdin` 也必须显式声明 |
| 4 | 等待子进程 | 直觉是 `wait()` | 句柄提供 **`done`**（`Promise<SubprocessOutcome>`）与 `waitForExit`，**没有 `wait`**。`'pipe'` 时原始流归调用方，必须与 `done` **并发排空** |
| 5 | `spawn` 的 `cwd` | 看着可选 | **必须显式传**。省略会抛 `TypeError: Cannot read properties of undefined (reading 'includes')`——来自一个在墓碑过滤**之前**运行的空字节校验，报错与真实原因无关 |
| 6 | 访问 `ctx.<service>` 的类型 | 服务在各自包里 | 必须 `import type {} from '<声明它的包>'`，否则 `Property 'x' does not exist on type 'Context'`。**已在 `slots`/`locale`/`systemPrompt`/`skills`/`sandbox`/`subprocess` 六处重复出现** |
| 7 | 依赖通道 | 按语义选 dist-tag | `@deepseek-ai/dsh-*` 的 **`latest` 是陈旧的 `0.0.1-rc.1`**，且经镜像安装会因依赖一个**从未发布**的包而失败。必须锁 **`alpha`** |
| 8 | 构建脚本门禁 | 以为只影响 git 安装 | **纯 npm 依赖同样会被 `ERR_PNPM_IGNORED_BUILDS` 拦下**（本次是 esbuild），profile 需要 `allowBuilds` |

## 二、客户端半（browser 半）

| # | 契约 | 类型怎么说 | 运行时实际怎样 |
|---|---|---|---|
| 9 | `clientBundle()` 的产物 | 以为只产出浏览器半 | **必须同时产出 node 半**。客户端包的 Loader 行按**裸包名**解析到 `lib/index.js`，缺了就直接 **`failed to import`** |
| 10 | eager / lazy 图 | 共享模块天经地义 | **eager 与 lazy 图之间不得共享任何模块**（最易犯的是共享 CSS Module）。rolldown 会把它提升为共享 chunk，入口出现**同步 `require("./client.x.js")`**，而加载器协议禁止 entry/chunk 同步 require |
| 11 | 插槽的 `form` | 文档与示例都暗示会传入 | `plugins.bundle.config` **永不传 `form`**（页面只传 `{ view: 'page' }`）；只有 `plugins.row.config` 由页面注入。**bundle 卡片必须自取** |
| 12 | 插槽的类型检查 | 照抄仓内 import | 必须 import **声明该插槽的包**；且 **`dsh-client-ui-slots` 只有 `.` 导出、没有 `/client` 子路径**，照抄仓内写法会报模块找不到 |
| 13 | `.volatile()` 的 Config | 教程示例带注解 | **不能加 `Schema<Config>` 标注**——`exactOptionalPropertyTypes` 下 `Volatile<string>` 与 `string` 冲突。教程示例是非 volatile 的，照抄就错 |
| 14 | 内容型工具输出 | `ContentBlock` 像在 tools 包 | `ContentBlock` 来自 **`@deepseek-ai/dsh-llm`**，不是 `dsh-tools`。且 `output.schema.type` 需要 **`as const`**，否则拓宽成 `string`，`execute` 返回类型退化为 `never` |

## 三、设置与 Plugins 页（**一个 row 牵涉三个不同的 id**）

| 用途 | 值 | 来源 |
|---|---|---|
| `plugins.row.config` 槽 key | `` `${bundle}#${rowId}` ``，如 `@znlgis/dsh-gis#gis-gdal` | `rowConfigKey()`，ledger 由**客户端槽注册**驱动 |
| `ctx.configForms.get()` 命名空间 | `entry.options.id`，如 `gis-gdal` | 宿主 `settings.describe()` |
| `li[data-plugin-row]` | Loader **entry id**，如 `include:gis-gdal` | DOM 属性 |

**混淆任意两个都静默失败**：没有异常、没有日志，只是入口不出现或表单不可写。

### 三条最贵的教训

1. **停用的行没有设置命名空间。** 症状是「表单存在但 `status` 为 `unavailable`」。我为这一个 checkbox 在客户端上改了三轮 id 拼写。判定顺序应当是：**先看行的启用状态 → 再看命名空间 → 最后才是 id 拼写**。
2. **`ctx.configForms.get()` 对不存在的命名空间不报错、不返回 undefined**，而是返回一个**看起来完全正常的表单对象**，`writable` 甚至为 `true`。**只有 `getSnapshot().status` 能分辨**。任何「取到表单就算成功」的判断都是错的。
3. **命名空间的发布有四条充分必要条件**（`settings/src/index.ts:302`）：条目被 `configEditor.configuration()` 收录、`entry.fiber.runtime.Config` 存在、schema 至少有一个 `.volatile()` 字段、`entry.fiber.state === ACTIVE`。**命名空间就是 `entry.options.id`，没有前缀换算规则。**

## 四、数据与格式

| # | 契约 | 运行时实际怎样 |
|---|---|---|
| 15 | `dataset.title` | 是**显示名**，对 shapefile 就是裸文件名。**永远不要进 argv**——GDAL 会拿它去工作目录里找，报 `No such file or directory`。按 kind 取 `dir`/`main`/`path` |
| 16 | 多几何体 WKT 序列化 | `MULTIPOINT` / `MULTILINESTRING` / `MULTIPOLYGON` 必须给**整个成员表**再包一层括号。缺了就是**无效 WKT**。三处同一系统性错误，只有 `parse → serialize → 断言等于原文` 的往返测试能发现 |
| 17 | GDAL 的价值 | `ogrinfo -j` 在 `coordinateSystem.projjson.id.code` 里**直接给出 EPSG 码**；手写 `.prj` 解析器只能靠名字猜。这是 GDAL Provider 存在的唯一理由 |

## 五、存储、缓存与生命周期（T1a.2 / T1a.10 实测）

| # | 契约 | 类型怎么说 | 运行时实际怎样 |
|---|---|---|---|
| 18 | `storageDomain.open()` 的生命周期 | 拿到 handle 就能用，`close()` 只是释放资源 | **域名单次占用，且 `close()` 是异步的**——名字要等 teardown 跑完才释放。背靠背重载（HMR、同进程重启）会撞 `already-open`；而 `open` 本身是异步的，失败一旦被 catch 掉就是**静默退回内存注册表**：没有异常、没有日志，只有「重启后 id 全没了」 |
| 19 | 可选服务依赖 | `static inject` 与 `ctx.inject` 看着等价 | **类插件的 `static inject` 是硬依赖**：服务永不到来 ⇒ 整行永久 `waiting-for-services`（没挂 storage 的 profile 里，GIS 会整块失效）。**`ctx.inject(['x'], cb)` 才是可选依赖**：服务出现即挂载回调、消失即卸载，回调内部再用 `ctx.effect` 管住打开的域 |
| 20 | 跨包错误判定 | `instanceof` 天经地义 | **同一个包既是我们的依赖、又是宿主挂载的服务时（`@deepseek-ai/dsh-storage-domain`），模块有两份实例 ⇒ `error instanceof DomainError` 恒为 false**。要按 `error.code` 匹配（宿主自己的测试也是这么断言的） |
| 21 | 异步初始化的组件 | 构造函数返回就等于可用 | **索引/扫描是异步建的，而 API 是同步的**：任何依赖它的操作若不自己 `await` 就绪，就会在**「本进程的第一次调用」**上静默少算——T1a.10 的 `clear()` 冷启动时确实删掉了 600 KiB，却报「释放 0 字节」。单测抓不到：测试路径总要先经过一个会 `await` 的调用，**只有真实进程的第一步走冷路径**。变更操作一律「在写链内先 await ready」，别信构造完成 |

> 第 18 条的后果是具体的：`already-open` **必须重试**（实现里给 4 次、退避 50ms），否则「改代码 → HMR 重载」会悄悄把持久化关掉，而症状与「profile 没挂 storage」完全一样。这条只在真实重载里现形。

## 六、客户端 bundle 与第三方库（T2.1 实测）

| # | 契约 | 类型怎么说 | 运行时实际怎样 |
|---|---|---|---|
| 22 | 引一个地图库 | `npm i maplibre-gl` 然后 `import()` | **版本决定能不能用**：maplibre-gl **6.x 是纯 ESM**，用 `new URL('./maplibre-gl-worker.mjs', import.meta.url)` 装载 worker——插件的 chunk 由 `/plugins/<pkg>/...` 提供，这个兄弟文件不存在，于是地图**静默起不来**。**5.x 的 UMD 把整个 worker 内联成字符串**并 `setWorkerUrl(createObjectURL(new Blob(...)))`，自包含。**引第三方浏览器库前，先读它怎么装载 worker** |
| 23 | `import()` → `require.async` | 动态 import 都会变成懒 chunk | **只对 ESM 成立**。CJS 包（如 UMD 版 maplibre）的动态 import 会被 rolldown 包成 `Promise.resolve().then(() => __toESM(require('./client.x.js')))`，预设的重写规则匹配不上，**构建期直接报「dynamic chunk has no generated import expression」**（响的失败，值得庆幸）。解法是加一层 ESM 包装模块，让互操作发生在 chunk 内部 |

> 第 22 条的普适性：**「能在 npm 上装」与「能在插件 chunk 里跑」是两件事**。任何自带 worker / wasm / 资源文件的浏览器库都属于这一类，判定依据是它装载这些资源的 URL 从哪来。

| # | 陷阱 | 看起来像 | 实际是 / 判定 |
|---|---|---|---|
| 28 | 子进程的「进度」在 Windows 上读不到 | 「GDAL 会往 stdout 打进度，按行/按块读就行」 | **管道不是终端**：C 运行库对 stdout 整块缓冲（4 KiB），41 秒转换的全部进度文本（约 60 字节）**直到退出才到达**——按行、按块都一样读不到。**判定：进度必须来自运行期间可观测的副作用**（这里是 staging 文件增长），子进程自己的输出只当「到了就用」的加分项（T2.11 实测，M2 退出验证逼出来） |
| 29 | 补丁里给「还不存在的插件」写行 | 裸写 `- id: 新插件` + `name:` | **`- id:` 只匹配已有行**；给新插件写裸行会被**静默忽略**（不报错、不加载）。新插件必须 `- insert:` + 缩进子行（T2.11 实测：探针连续三轮「什么都没看到」） |
| 30 | 看别人的后台作业 | `ctx.jobs.list()` | **只返回无主作业 + 调用者自己的**；要看全部必须订阅 `ctx.jobs.events`（`{ owners: 'all' }`）。且入口是 **`ctx.jobs.events.subscribe`**——写 `ctx.jobs.subscribe` 会让**整个实例启动失败**（T2.11 实测） |
| 31 | chunk 之间同步 `require` | 「rolldown 产出的 chunk 互相 require 是正常的」 | **不成立**：loader 的 `require` 只认平台种子 / 已 materialize 的模块 / 已登记的 factory ⇒ 同步 require 兄弟 chunk **只在它恰好先被加载时**才成立，顺序没有保证。rolldown 只要发现两个动态 chunk 共享模块（运行时辅助、`basedecoder`、`pako`）就这么发。症状是一次内核升级后**整条地图路径不再渲染**，报错 `require("./client.rolldown-runtime.js") missed the module table`。**判定：没有任何 chunk 同步 require 另一个 chunk**；修法：构建后把被同步 require 的 chunk 内联掉（T2.5 实测） |
| 32 | `exports` 的 `browser` 条件 | 「声明了 `browser` 就会走浏览器构建」 | **条件按包里的书写顺序匹配**，不按调用方请求的顺序：geotiff 把 `import` 写在 `browser` 之前 ⇒ 客户端包进的是 **Node 版 ESM**，它经 `web-worker` 摸到 `http` ⇒ `require("http") missed the module table`。**判定：客户端依赖要么验证它真的进了 browser 构建，要么在预设里显式指向**（T2.5 实测） |
| 33 | 卡片不接控制器的 issue | 「规范化有 issue 就够了」 | 控制器/绘制阶段的失败（栅格解码失败、图层被 MapLibre 拒绝）**必须也进卡片**，否则「画不出来」变成一张静默空白图——正是本项目最在意的失败。T2.5 实测：解码报错只出现在控制台，卡片一个字都不说 |
| 34 | 内核 alpha/rc 漂移 | 「peer 不匹配会报错」 | **是静默跳过**：`dsh` 打印 `skipping profile bundle "@znlgis/dsh-gis"` 然后**整个插件不加载**（所有实例检查同时红，看起来像插件坏了）。**判定：每次升级内核都跑一遍六条实例检查**（T2.5 实测：0.1.7-alpha.2 → rc.1 仅需升版本，无 API 破坏） |
| 35 | 依赖里的 Node 代码路径 | 「用不到就无所谓」 | **模块顶层的一次 `require("module")` 会让整个 chunk 加载失败**（`missed the module table`）：pmtiles 的 `FileSource` 就是如此，而浏览器里永远用不到它。**判定：客户端依赖要么走真正的 browser 构建，要么为 Node 内置提供「调用即抛」的桩模块**——桩让用不到的路径无害、让真的走到它响亮失败（T2.5 实测） |
| 36 | 「范围总是宿主知道」 | 自带空间索引的容器（FlatGeobuf / PMTiles）在宿主侧**没有** extent——只有读了才知道 | `bbox` 允许为**空数组**，含义是「客户端自框定」；空 extent 在规范化里**不算缺陷**（否则正确的卡片带一条莫名告警），客户端按读到的数据或归档头 `fitBounds`（T2.5 实测） |
| 37 | 持久化日志是**多帧** zstd | 「`zstdDecompressSync`/`createZstdDecompress` 能把文件解开」 | **两者都只解第一帧**：实测 18 KB 日志有 4 帧（magic 在 0/223/370/682），第一帧只装会话头部 ⇒ 症状是「日志里一个事件都没有」，极易误判为刷盘时机（T2.11 就这么误判过一次）。**判定：自己按 magic 切帧逐帧解码，切不动就向后放宽**（T2.9 实测） |
| 38 | 仓外插件自造会话事件类型 | 「`session.append('my/event', …)` 就行」 | **读路径拒绝未知类型**（`KNOWN_SESSION_EVENT_TYPES`），而 `Session.append` **不暴露** `ignorable` 标记 ⇒ 自造类型的日志换一个构建就读不出来，**是插件自己毁掉自己的会话**。**判定：插件应折叠已有事件**（`tool/result` 的 `meta` 等），而不是新增词汇（T2.9 实测，设计 6.5 的写法据此修正） |
| 39 | 「一个模块被两个动态导入者引用也无妨」（#31 补充） | 第一次修 #31 时定的规则是「**调度器 chunk 一律内联跳过**」 | **太严**：共享地图组件既是调度器（按需加载各读取器）**又是两个预览体的依赖** ⇒ 规则一放宽，bundle 立刻又出现被禁的同步 require。**判定：唯一的跳过条件是「内联会自嫁」**——即目标 chunk 能（经同步或异步边）到达引用者。按这条规则，共享组件被内联进每个消费者（各一份），没有任何同步 require（T2.8 实测） |
| 40 | 「worker 里 fetch 相对 URL 没问题」 | worker 由 **Blob URL** 创建 ⇒ **相对 URL 相对 `blob:` 解析** | `fetch('/api/gis/blob?id=…')` 变成 `blob:http://host/api/…` ⇒ 网络错误、**0 次 Range 请求**、错误文案只有「Request failed」。**判定：主线程用 `document.baseURI` 解析成绝对 URL 再交给 worker**（T2.10 Worker 化实测） |
| 41 | 「把共享函数序列化进 worker 可防漂移」（前一条的自然想法） | **会制造 chunk 环**：worker 需要 import 该模块 ⇒ worker chunk 与持有它的 chunk **互相 require** ⇒ 加载器报 `missed the module table`（#31/#39） | **判定：让跨边界的数据不需要共享代码**——worker 只回**原始样本**，RGBA 展开留在主线程；防漂移由架构达成，而不是字符串拼接（实测） |
| 42 | 「插件在隔离 cordis 里能注册，Loader 里也一定能」 | **不一定**：同一个构建产物 `ctx.plugin(module, config)` 正常发布服务，而作为 Loader 行（绝对路径 + config）插入时**服务不出现、且日志里没有任何告警**（探针能加载，说明路径插入本身没问题） | **判定**：行装配失败**可能是静默的**（只对被禁用的行有 warning）；定位时先用探针报「我加载了 / 服务在不在」三段，别再从包本身找原因（T3.1 实测，未闭合，线索见 T3.1 记录第五节） |
| 43 | 「构建没报错就是构建成功」 | 新包缺 `tsdown.config.ts` ⇒ 产物落在 `dist/`，而 `package.json` 的 `main` 指向 `lib/`；命令退出码 0、无输出 | 真实例表现为 `failed to import`；我因此白查了三轮。**判定：断言产物存在**（`Test-Path lib/index.js` / `node -e import(...)`），而不是断言「没有错误输出」（T3.1 实测） |
| 27 | 照抄手册里的外部工具参数 | 「文档写了 `gdal_translate -of COG -progress`，照抄即可」 | **GDAL 3.13.3 删掉了 `-progress`**，传了直接 `ERROR 1: Unknown argument: -progress`（进度往 stdout 打**已是默认**，只有 `-q` 关掉）。照抄的后果是「手工敲同一行能跑通，插件里每次都失败」。**判定：外部工具的每个参数都要在本机那一版上真跑一次**，别拿文档当事实（T2.4 实测）。<br>同源一条：**解析进度不能取行里的任意小数字**——同一股输出还有 `Input file size is 1, 1`，那样的解析器会把文件大小当 1% 进度，**失败时也让进度条前进**；先判形状（`...` 连接的数字 / `100 - done.`）再取值 |

## 七、共享模块与陈旧产物（T2.2 实测）

| # | 契约 | 类型怎么说 | 运行时实际怎样 |
|---|---|---|---|
| 24 | 跨 eager/lazy 的共享模块 | 「第 10 条说的是 CSS Module」 | **任何**模块都算。T2.2 里 eager 的探针卡片 `import` 了 lazy 图里的 `layer-model.ts`（一个纯函数模块），rolldown 立刻把它提升成**共享 chunk**，入口于是出现**同步 `require("./client.layer-model.js")`**，加载器解不了 ⇒ **工厂抛错 ⇒ 该插件的样式标签整批消失**。症状是「插件没加载」，根因是一个 import。**第二种触发器（T2.6 实测）**：一个模块被「两个动态导入者 + 一个静态导入者」引用，同样被提升——于是卡片 chunk **同步 require** 组件 chunk。触发条件不重要，判据才重要：**没有任何 chunk 被同步 require，且每个 chunk 都能从入口经 `require.async` 到达** |
| 25 | 客户端构建的 `lib/` | 改了源码重建就干净了 | 预设的 `clean: false` 是**有意的**（默认清理会连带删掉同目录的 node 半与 `types/`），代价是**离开依赖图的旧 chunk 会一直留在 `lib/`**，被 `files: ["lib/client.*.js"]` 发布出去、还可能被加载器照旧服务。构建前先清 `client.*.js`，并在产物里断言**没有孤儿 chunk** |

> 这两条一起构成一条更普适的规则：**客户端的「构建成功」不代表「产物自洽」**。真正的判据是产物图的两条性质——入口不静态 require chunk、每个 chunk 都能从入口到达——而它们只有对着 `lib/` 才能检查。

| 26 | 注册一条给浏览器的路由 | `ctx.webServer.register` 与 `ctx.connection.fetch.register` 都能注册 | 前者**在鉴权栅栏之外**，后者在栅栏之内（设计 3.5：GIS 的字节必须走后者）。两个实测事实：**栅栏真的拦人**（进程外直接 fetch 该路由得不到 200）；**路由注册是一个 effect**，插件卸载后残留的 handler 会因 context 失活而拒绝服务——这正好是 HMR 想要的。另：`connection.fetch` **只做 exact pathname 匹配**，路径段参数（`/tile/<z>/<x>/<y>`）永远不命中，一切走 query |

## 九、方法论

1. **「类型正确」与「运行时寻址/生命周期正确」是两件事。** 本文 43 条里有 39 条属于后者。
2. **真实实例验证不可省。** `Proxy` 吞私有字段、停用行无命名空间、`title` 当路径——**没有任何一条能被单元测试发现**。M0 之所以要设一道真实实例门，就是为此。
3. **但真实实例并非唯一手段。** M1b 的 GDAL 链路靠**结构化解耦**（把 `runtime.run` 抽成接口）在单元测试里驱动了真实二进制——**不需要模型凭据**。遇到「必须起实例/必须有凭据」的判断时，先问一句：真正的依赖能不能抽出来。
4. **断言要断言结构，不要断言「跑成功了」。** 出图测试断言「颜色多于 3 种」和「孔洞中心等于背景色」，而不是「文件生成了」；WKT 断言往返相等，而不是「解析成功」。本文一半的 bug 是这类断言抓出来的。
5. **跨进程语义可以在单测里造：新 `Context` + 同一份真实介质。** T1a.2 的「重启后 id 还在」就是这么测的——用真实的 `dsh-storage` / `dsh-storage-json` / `dsh-storage-domain` 指向一个临时目录，**不需要凭据、不需要起实例**。
6. **对关键断言做一次变异检查。** 把实现改坏，确认断言真的会红：T1a.10 里把淘汰循环短路 ⇒ 6 条失败。不做这一步，你分不清「测试通过」和「测试没测到」。
7. **但 Loader 装配只有真实实例能证。** 单测证明了注册表，证明不了「我们的行在真 profile 里是否激活、可选注入是否绑上 dsh-base 挂的 storage」。把这类验证**写成可重跑脚本**（`scripts/t1a2-real-instance.mjs`：临时介质 + 关掉 webserver + 探针插件 + 三次真实启动），比一次性手工操作值钱得多。
