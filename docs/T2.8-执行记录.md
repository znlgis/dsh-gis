## 三、两条设计决定

1. **两个定义，不是一个。** `loading` 是**定义**的属性（`text-pages'` / `bytes-complete'`），一个定义不可能同时是两者，所以文本与二进制分开注册、各配一个体（id 即槽位 key）。
2. **不认领 `.json`。** 元数据里刻意不含 `json`：一个不是 GeoJSON 的 JSON 文件应该由宿主文本预览打开，认领它只会把「地图画不出来」推给一个只想读配置的人。

## 四、实测

- **单测 10 条**：定义形状（`priority`、二进制后缀必须都在 extensions 内、两种 loading）；**不认领 `.json`**；GeoJSON → 一个 data URL 图层、无 bbox（由 MapLibre 自框定）；不是 JSON / 不是 GeoJSON / `.wkt` 未实现 / **超 8 MB 拒绝** 各自给理由；`.fgb/.tif` 计划为解码、`.pmtiles` 与超 48 MB 的栅格被拒且**点名指向卡片**。
- **web 车道 6 条**：真组件 + 真 fixture + 假 MapLibre —— GeoJSON 真的挂载地图；非 GeoJSON 出理由**且原文仍可读**；`.wkt` 出「未实现」；**真 `points.fgb` 解码后在共享地图上画出**；`.pmtiles` 出「用 GIS 工具打开」；**损坏的 `.tif` 出一句话而不是空白**。
- 全量：节点 **194 通过 + 1 跳过**、web **13 通过**、产物契约 ✓。

## 五、🔴 抓到的：共享 chunk 的第二次复发（契约 #31 的规则要放宽）

加预览体后 bundle 又断了同一类：**共享地图组件被两个预览体 + 卡片引用** ⇒ 被提升成独立 chunk 并被三方**同步 require**。根因是我第一次修 #31 时定的规则太严——「调度器 chunk 一律跳过内联」，而这个组件**既是调度器又是依赖**。放宽后的唯一跳过条件是「内联会自嫁」（目标能到达引用者）✓，于是共享组件被内联进每个消费者（各一份，各自只下一次）✓ 产物契约恢复 ✓。契约 #39 记之。

## 六、诚实边界（重要）

1. **注册本身与真实点击路径未验证。** 要证明「在真应用里打开 `.geojson` 会走**我们的**预览而不是宿主文本预览」，需要在真实例里把工作区指向隔离目录并驱动侧栏（展开右栏 → 文件面板 → 点文件）。本轮侦察发现：实例的默认工作区仍是**用户目录下的「默认工作区」**，把 fixture 放进去会污染用户机器 ✗，而工作区重定向的配置面未找到。因此：
   - **单元 + web 车道**覆盖了定义、解析、拒绝与渲染 ✓；
   - `priority:'extension'` 的**排名**只由「定义里声明了它」间接证明（真正的排名是宿主的规则，本轮未在真宿主上断言）✗；
   - 「浏览器里工厂没抛错」由 `check:browser` 间接保证（注册失败会带崩插件工厂 ⇒ 样式标签消失）✓。
   **这一条应作为 T2.10 的补项**：那里已经有可控的会话与浏览器，只差一个隔离工作区。
2. **`.tif` 走 `bytes-complete`**：文档所有者交的是**完整字节**，所以 48 MB 以上直接拒绝而不是流式（设计写的是 `'renderer'`，但 `renderer` 要求自取，而字节路由按**数据集 id** 寻址、预览按**路径**打开，两者之间没有桥）。这是本轮最大的实现偏差，已在代码注释与拒绝文案里说明。
3. **`.shp/.gpkg/.pmtiles` 只被认领、不渲染**：它们会得到一句「用 GIS 工具打开」，而不是空白。
4. **缩放/平移、导出动作、`.unpreviewable` 卫星插槽未做**（设计 L1 的后半）。
5. **不做对比度拉伸**：栅格按位深线性映射，窄值域会看起来接近纯色。
