## 三、判据是「机械成立」的，不是「文档建议」

schema 用 `z.strictObject` 且**没有** password 字段 ⇒ 配置里写 `password: …` **直接加载失败并点名该键** ✓。这比「写文档提醒不要放密码」强，也比「只允许从环境变量读」强——后者仍然允许被写下来。

## 四、实测（9/9）

- **明文密码被拒**（两种形状：裸的、以及从别的工具迁移过来最可能写的那种）✓

- **`describe()` 只调用 credentials 的 `describe`，从不调用 `resolve`**（用记录型解析器断言调用序列）✓，且返回值里没有密钥 ✓

- 无凭证服务时降级为 `unavailable` ✓；无该剖面 → `undefined` ✓；缺密钥 → 可执行的报错 ✓
- 全量回归：节点 **205 通过 + 1 跳过**、浏览器检查 ✓

## 五、🔴 未闭合：真实例装配（诚实记录）

**探针能加载、服务不出现，且没有任何告警。** 过程与结论：

1. 尝试在实例里插入一行（绝对路径 + 配置），探针报告 `ctx.get('gisPostgis')` 为 `undefined` ✓（探针本身加载成功 ✓）。
2. **同一个构建产物在隔离 cordis 里完全正常**：`ctx.plugin(module, config)` → 服务在 ✓、`describeAll()` 正确 ✓。⇒ 问题在 **Loader 装配**，不在包。
3. 试过的两种补丁写法都无效：`- insert:`（行）+ 单独 `- id:`（配置），以及把 config 写进 insert 条目 ✓（都不是原因 ✗）。
4. 途中还排除了：**新包没有构建产物**（`tsdown.config.ts` 缺失 ⇒ 输出到 `dist/` 而 `main` 指向 `lib/`；我把「Select-String 没输出」误读成「构建成功」，正是本项目「断言结构而不是『它跑了』」那条纪律的反面教材 ✓ 已修）✗。
