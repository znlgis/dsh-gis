## 三、两个决定（决定这条 SQL 是「快」还是「全表扫」）

1. **相交判断在图层自己的坐标系里做**：显而易见的写法 `ST_Intersects(ST_Transform(geom, 3857), tile)` 会**变换每一行**，于是 **GiST 索引完全用不上**；改为把**瓦片包络**变换到图层 SRID，用 `&&` 让索引生效 ✓（单测断言 WHERE 里是 `ST_Transform(bounds.tile, …)` 且**不是** `ST_Intersects(ST_Transform(t.…`）。
2. **没有 SRID 的图层拒绝出瓦片**（`CRS_UNKNOWN`）：猜 4326 会把投影数据放到「看起来很像但错」的坐标上，比拒绝更糟 ✓。

## 五、诚实边界

1. **瓦片还没接进 HTTP 路由**：`tile()` 已在服务上可调用，但 `/api/gis/tiles/...` 与前端渲染要走 T3.6；本轮交付的是「库能直出瓦片」这件事本身。
2. **每瓦片要素上限 20000 是护栏**：达到上限时**静默截断**（瓦片场景的通行做法：靠提高缩放级别解决），但本实现没有把「被截断」暴露给调用方——这是已知的诚实缺口。
3. **属性列由调用方给**：没有自动挑选（全带会撑大瓦片），T3.6 再接。
4. **未测并发与缓存**：没有 ETag/缓存头，也没压测同一瓦片的重复请求。
