## 三、真 GDAL 实测（20/20）

- 多图层 `.gdb` **报出全部要素类**（`cities`、`projected_areas`）✓，并给出「需要指定 layer」的 `LAYER_AMBIGUOUS` ✓
- **逐层**：每层都能**单独描述** ✓、都能**读到要素** ✓、都返回几何 ✓（判据 ✓）
- 未知名 → `LAYER_NOT_FOUND` ✓；多图层容器上不指定 layer → **`LAYER_AMBIGUOUS`** ✓
- 工具侧：`layer` 出现在三个工具的 schema 里 ✓；到达 `ctx.gis.query` ✓；**`gis_render` 的两次调用都带同一个 layer** ✓✓

## 四、多图层 fixture 立刻抓到的两个真问题

1. **指定 layer 的 `inspect` 仍返回全部图层** ✗：extent/fields 取自**第一个**图层，却看起来像在描述你点名的那层 ⇒ 改成只描述该层 ✓。
2. **多图层容器上不指定 layer 的 `query`**：`ogr2ogr` 的回答是一个**空消息的错误**（实测 ✗）⇒ 改为**我们自己**给出 `LAYER_AMBIGUOUS` 并说明有几层、该传什么 ✓。读「碰巧排第一」的那层是最像正确 yet 不正确的答案。

这两条都是只有**多图层 fixture** 才能暴露的——单图层测试永远发现不了 ✓。

## 五、诚实边界

1. **`.gdb` 数据集的 `layers` 字段仍是占位**（以目录名命名 ✗）：真正的图层清单来自 `inspect`/handler 的 `ogrinfo` 结果 ✓。因此**注册表里那份 dataset 记录不反映真实图层**——若将来有 UI 直接读 `dataset.layers` 来画图层面板，会看到占位名 ✗（T3.6 未处理，因为 opener 是同步的而枚举需要跑 GDAL）。
2. **PostGIS 侧的多图层未接**：本轮只把 `layer` 打通到 GDAL 路径；PostGIS 的目录/分页/瓦片仍是服务层可调用（未进工具）。
3. **`query` 的 layer 校验依赖一次额外 `ogrinfo`**（仅在未指定 layer 时发生 ✓）；指定 layer 时不额外调用 ✓。
4. **`gis_render` 的图层选择只影响取数**：图仍是等距圆柱投影的快速预览（设计如此）✓。
5. **未测并发与超大数据**：fixture 只有 63 KB。
