docs: T3.8 — M3 exit verification (G4 satisfied)

Every one of M3's five exit criteria now has a re-runnable check behind it:

1. .gdb all layers visible -- check:gdb 20/20: a multi-feature-class geodatabase
   reports every layer, each can be described on its own and READ with geometry;
   unknown layer -> LAYER_NOT_FOUND; missing layer on a container ->
   LAYER_AMBIGUOUS
2. version diagnostics as KEYS (read >= 1.11 / write >= 3.6) -- 12 unit tests on
   the exact boundaries, and an old version is refused without invoking the
   binary at all
3. slow query -> SQL_TIMEOUT -- a 500 ms cap cut a pg_sleep(3) off in under 2.5 s,
   i.e. the SERVER stopped it rather than the client waiting it out
4. injection -- 13 live assertions: the filter arrives as $1, the value is absent
   from the SQL text, a statement terminator matches nothing AND leaves the table
   untouched, a column outside the whitelist is refused by name
5. ST_EstimatedExtent NULL -- an un-analyzed table reports UNKNOWN (-1) rather
   than zero, with an actionable reason, and is still listed

The record also lists what is deliberately NOT done: PostGIS is not wired into the
tools yet (it works and is verified at the service layer, but the model cannot see
it -- the first task after M3), the gis-postgis bundle row is still unmounted, no
low-version GDAL environment exists (the gates are covered by injectable
versions), no containerised PostGIS (the local 17.5 + PostGIS 3.5.2 carried every
criterion), and no fuzzing.

M3 is marked satisfied in the plan. 255 node tests + 1 skipped, 13 web tests,
bundle contract OK, twelve re-runnable checks.
