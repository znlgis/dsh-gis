feat: T3.9 — PostGIS reaches the tools (the first task after M3)

The M3 exit record listed this as the one thing standing between a working
service layer and a usable feature: the catalogue, paging, tiles and the filter
were all verified against the live database, but the model could not see any of
it, because nothing claimed a database as a dataset.

What landed
- an OPENER for postgis:<profile>[/<schema>.<table>], kept a pure factory as
  gis-core requires: it parses the address and describes the dataset without
  connecting, and the layer list it returns is a placeholder that inspect()
  replaces with the catalogue's truth
- a HANDLER for kind 'postgis': inspect (every reachable spatial table, SRID,
  estimated extent, fields, tiles: true, and an issue that SAYS the numbers are
  estimates) and query (bound where, paging, geojson/wkt, layer addressing)
- both registered through an OPTIONAL ctx.inject(['gis']), so a profile without
  gis-core still loads this row (contract #19)

Verified in a real instance (check:postgis-tools, 14 assertions) using the same
ctx.gis facade the tools use: the opener claims the address, the dataset gets a
derived id and carries the PROFILE name rather than any password, inspect lists
every fixture table with its SRID and estimated extent and labels the estimate,
query returns a real page with GeoJSON geometry and attributes, a where filter
reaches the database through the tools path, and wkt encoding is honoured.

One trap, now contract #50: resolve() takes an ID and open() takes a PATH. The
probe used resolve() with a path and got "not registered (it may have been moved,
edited, or never scanned)" -- a message pointing at the filesystem while the
mistake was the call.

Two environment changes worth knowing: the user's profile gained a link
dependency on the new package (plus a directory junction, no network needed), and
the bundle patch now mounts the row -- restart the GUI to load it.

All real-instance checks still pass, 255 node tests + 1 skipped, 13 web tests,
bundle contract OK.
