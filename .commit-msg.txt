feat: T2.5 — browser-side direct read (COG, FlatGeobuf, PMTiles by range)

Both halves of T2.5, including the COG direct read that closes T2.4's leftover.

Client (packages/ui-gis)
- COG: ranged decode with geotiff, capped window, projected rasters refused
  rather than drawn in the wrong place
- FlatGeobuf: R-tree search driven by the VIEW rectangle, 20k feature cap
- PMTiles: vector layers from the archive's own metadata, a MapLibre protocol
  handler serving individual tiles
- one decoded-layer seam for all three, each reader in its own lazy chunk
- client-decoded layers skip synchronous description: describing one fetched a
  raster as if it were GeoJSON
- the controller's draw issues now reach the card (a silent blank map was
  possible before)
- an empty extent means "the client frames the data" (self-indexed containers
  cannot state one before they are read)

Host (gis-core, gis-purejs, gis-gdal, tool-gis)
- flatgeobuf and pmtiles dataset kinds, openers, byte-route media types
- gis_render's client-decoded branch: no server-side PNG, optional extent

Build
- flatten cross-chunk synchronous requires: the loader resolves require() only
  against the platform seed and materialized modules, so a chunk requiring a
  sibling chunk breaks whenever load order is not guaranteed. Rolldown emits
  that shape whenever two dynamic chunks share a module, and it broke the whole
  map path after the kernel move to 0.1.7-rc.1. The flattener inlines those
  chunks, never a dispatcher, and never deletes an async target
- stub Node builtins for the client bundle: pmtiles reaches
  require("module").createRequire at module scope, which fails the chunk
- prefer a dependency's browser build when its exports list import first

Verified
- 178 node tests + 1 skipped, 7 web-lane tests
- eight re-runnable instance checks: real, route, browser, e2e, exit (1.9 GiB
  GeoTIFF), cog, vector (FlatGeobuf + PMTiles by range in a real browser)
- fixtures generated by GDAL and committed

Docs: T2.5 record (both halves), 36 runtime-contract traps, plan updated.
