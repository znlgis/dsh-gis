docs: T2.8 preview check — mechanism found, boundary still open

Attempted the T2.8 browser boundary (does a .geojson preview actually show the
MAP instead of the built-in text preview?). The registrations and the ranking
still are not verified end to end, and this records exactly why, so T2.10 can
start from here instead of rediscovering it:

- DSH_HOME isolates the whole harness home (storages, sessions, workspace
  table), but it moves the PROFILE directory with it: the instance then cannot
  find "gisweb" and never boots. Copying the real profile directory into the
  isolated home fixes that (read-only input; the run writes only under it).
- With an isolated home the workspace table is EMPTY, and workspaces are
  bootstrapped from session headers (their cwd). A hand-seeded
  session.v4.jsonl.zstd (single frame, real header shape, cwd = the isolated
  directory) was NOT picked up: the sidebar still showed the placeholder
  workspace, no session, and therefore no file tree to click.
- Next step is the store's directory/naming convention and whether its reader
  needs the multi-frame layout. Both are cheap to check and neither was reached.

The failing t2-preview-check.mjs was deleted rather than committed: a check that
stays red is worse than none, and the mechanism above is the useful artifact.
