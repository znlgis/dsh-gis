Pagination (packages/gis-postgis/src/query.ts)
- LIMIT/OFFSET are validated whole numbers (refused above the cap, never silently
  clamped: returning 500 of the 5000 rows someone asked for is the kind of lie
  that ends up in an export)
- the page is ORDERED. LIMIT/OFFSET without ORDER BY has no defined order and
  repeats or skips rows without saying anything, so the order key is the primary
  key, or ctid for a table that has none -- and the page REPORTS which one was
  used. A composite key also falls back to ctid rather than pretending one column
  orders it.
- geometry is encoded by the DATABASE (ST_AsGeoJSON, with a ::geometry cast for
  geography), so a page carries coordinates rather than WKB hex
- identifiers go through quoteIdent; a catalogue name is still quoted, because
  PostgreSQL allows a table called we"ird

Verified on the live server (check:postgis-live now 35 assertions, 15 new):
- a slow query under a 500 ms cap returns SQL_TIMEOUT and is cut off by the
  SERVER in under 2.5 s -- not waited out and then judged
- writes are refused by the DATABASE in both profiles
- page 2 does not overlap page 1 (which is what proves the ordering is real)
- a table with no primary key pages by ctid and says so; a geography column pages
  and encodes; attributes cross JSON-safe; the spatial and carrier columns stay
  out of the properties
