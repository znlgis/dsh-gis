fix: T3.1 closed — the Loader row assembles, and two startup traps it hid

The row never loaded because of its ENTRY SHAPE. A module that exports only
`apply` is not assembled as a Loader row at all: nothing is identified, no
service appears, and the log carries NO warning. The fix is the shape gis-core
and gis-gdal already use -- `export default class PostgisService extends Service`.

With that, check:postgis passes 12/12 in two real instances:
- the row publishes ctx.gisPostgis; both profiles are described; the reference in
  the isolated credentials file reads CONFIGURED; a profile with no credential
  says not-required; the defaults reach the running service; every required
  plugin is active; and the SECRET appears nowhere in the instance log
- the bad side, in its own work directory: a profile carrying `password:` keeps
  the service from being published without taking the harness down, the probe
  still runs, and the rejected VALUE is not echoed

Two more traps, both of which made the harness fail to start while pointing
somewhere else entirely:
- a credential REFERENCE must match /^[A-Za-z_][A-Za-z0-9_]*$/ -- a hyphen made
  the credentials plugin fail to parse its document, which failed the whole
  startup with a message about a plugin the user never configured. Our schema now
  enforces the same regex, so the mistake is caught where it is made.
- the credentials document is `version: 1` with `refs:` nested; the flat
  pre-release form fails the credentials row, and the symptom is "the probe never
  reports", which is very far from the cause.

Also fixed: the service read `ctx.credentials` in its CONSTRUCTOR, so every
profile reported "unavailable" while the same configuration passed every unit
test -- the tests handed the resolver in directly, which is exactly the
difference the instance exposed. It is now a per-call getter, and the ten tests
pass the getter too.

Contracts #42 (settled, with its cause), #44 and #45 record all of it. 206 node
tests + 1 skipped, 13 web-lane tests, bundle contract OK.
