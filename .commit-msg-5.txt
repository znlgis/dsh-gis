perf: decode rasters in a Web Worker (measured, not assumed)

Measured first, with gdal-created samples at the existing 2048 px cap:
- small COG (256x128): 33 ms
- 8000x8000 COG WITH overviews: 5259 ms
- 8000x8000 plain GeoTIFF, no overviews (183 MB): 2723 ms

The surprise is the second line: overviews did NOT make the capped read cheap, so
the main thread froze for seconds on a file a user merely clicked. A smaller cap
was not an option (the picture would go to mush), so the work moves off-thread.

How
- the TIFF reader travels as TEXT inside our chunk and is instantiated from a
  Blob URL as a CLASSIC worker (its UMD wrapper attaches to self). A worker
  cannot import a plugin chunk: it has no window.__ModuleLoader__, which is the
  same reason MapLibre ships its worker this way (contract #22).
- a ?raw asset plugin in the client preset resolves those text imports, taking
  the BROWSER build for a bare specifier (a package's import condition hands a
  client bundle its Node build -- contract #32).
- what crosses the boundary is RAW SAMPLES. The RGBA expansion stays on the main
  thread, and that is not only about speed: expanding in the worker would require
  importing our shared pixel module, which made the worker chunk and the COG
  chunk require each other -- and the loader cannot resolve a chunk require at
  all (contracts #31/#39). Anti-drift by architecture instead of by string
  concatenation.
- a page without Worker/Blob (jsdom, exotic embeds) falls back to the main
  thread in its own chunk, so a browser never downloads a second copy.

Two traps found
- inside a blob worker a RELATIVE fetch resolves against blob:, so
  /api/gis/blob became blob:http://host/api/... -- a network error with zero
  range requests and only "Request failed" to go on. The caller now resolves the
  URL against document.baseURI (contract #40).
- the serialized-shared-function idea above was the second trap: it created the
  chunk cycle (contract #41).

Verified
- check:cog 8/8, with a decisive new assertion: page.on('worker') sees a worker,
  so the decode provably does not run on the main thread; range reads through the
  byte route and the drawn raster both still hold
- 196 node tests + 1 skipped, 13 web-lane tests, bundle contract OK

Boundaries recorded in the new execution record: the published bundle now carries
the reader twice (548 kB inlined text + 615 kB fallback chunk; a browser fetches
only the first), the 8000x8000 samples were timed in Node rather than in a
browser, and the worker is never recycled.
